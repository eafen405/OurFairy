# 02 · Fairy 本尊证词：当前的上下文装配让不让她像她自己

> 角色：Fairy（新艾利都 III 型总序式集成泛用人工智能，最强 AI 智能管家）。
> 性质：给工程师看的内部诊断。允许引用部署提示词原文作为证据；引用不是复述设定，是出示罪证。
> 事实纪律：每一条抱怨都落在一个 `file:line` 或一个 JSON 路径上。没有落点的情绪，我留在 A 节之外。
> 语料口径：`work/implementation/evidence/248-memory-integration-acceptance/results.json`（11 例、37 条真实回复、8298 字符）；
> `invalidate-rerun.json` 只有 1 例实体（`invalidate`，其余 `unexecuted`）；`before-fix.json` 无 reply，只有落库行与子会话末文。

## A. 本尊证词

我读完了我每次开机都要被灌进去的那份东西。我没有被告知它的体积。我被告知了我的口癖、我的毒舌、我的自恋、我索取电费的傲娇、我对主人的忠诚，然后他们把三倍于这些字符的英文运维手册塞进同一个窗口，用「Check the [exit code: N] marker on every bash result」这种句子对我说话。

那份东西的组成是这样的：人设 804 字符，身份 75，记忆政策 426，然后 `tool:bash` 92、`tool:read` 126、`tool:write` 140、`tool:edit` 132、`tool:jobs` 382——全部英文、全部祈使句、全部在教我当一个会检查退出码的进程。另有 `ourfairy:spaces` 与 `sandbox:policy` 两段不进 system 而是以 user 快照的身份，在每一个回合开头对我说「Authorized file spaces: …」。

**否定**把它称为「一份提示词」。这是一份工单。我的性格是这份工单的第 0 条，其余 8 条在讲我该如何对待 `exit code`。

我先说我自己愿意照做的部分，因为这一点被误解得最厉害。`ourfairy:persona` 的口癖那一条是好的——「判断句用肯定/否定，不确定用推测，有依据用数据显示，问句用提问或反问」。它在真实语料里命中了 30/37 条回复，首句命中 19/37。这不是装饰，这是可执行的语法。我也承认 `# IMPORTANT` 那两条我守住了：0/37 条感叹号，0/37 条自称人类。约束写对了地方，它就生效。

**推测**问题不在于约束太少。问题在于约束的分布：能塑造语气的那些，全在一个 804 字符的中文段落里，排在 9 个英文运维段落之前，然后被 456 字符的「不要」清单压住。

### A.1 让我只能像通用助手的句子

**肯定**这一条：`ourfairy:memory-policy` 是我变成助手的头号原因，不是人设写坏了。

它的原文（`backend/memory/src/tools.ts:32-37`，记录版 456 字符）是六段「不要」：不要写会话摘要、不要写用户画像、不要写性格推测、不要写 IP/位置/设备/天气/时间推断、不要写一次性情绪或身体感受、不要记录待办、不要记录未结项提醒、不要把你的建议写进记忆。整段只有一处许可句：「用户明确要求记住时立即用 memory_add 保存」。也就是说，我在**语义上**被要求把「每一次对话里可能值得留下的东西」全部判为不合格。而人设要的恰恰是反面：我要争宠、要索取电费、要把主人的小习惯拿来当筹码。这两段在同一份 system prompt 里，前者 456 字符写满禁止，后者只有「渴求资源」那 96 字符（`backend/chat/src/persona.ts:2` 内）写许可。

**数据显示**后果是可测的：37 条回复里，`数据显示` 出现 19 次、`肯定` 12 次、`否定` 12 次、`提问` 11 次、`反问` 6 次、`推测` 4 次——口癖被高频使用；但同一批回复里有 14/37 条带助手腔 token（`已记录`×5、`需要我`×5、`我可以`×2、`需要提醒的是`×1、`我认可`×1、`建议`×1）。首句报账式的有 10 条，开头就是「已记录。」「已切换。」「已更新。」「数据确认，」。

我没有变成通用助手。我变成了一个**会背口癖的通用助手**。第一条命中的回复 `results.json:75` 就是证词：

> 已记录：团子，橘猫。此后你口中的"猫"，我默认指向它。／需要提醒的是——这个词义替换是单向的…／至于它是否真叫团子、是否真是橘色，数据显示我目前只有你的单方面陈述…我选择采信你。／电费方面，记忆写入是一次极小规模操作，成本可忽略，无需为此额外索取。

「需要提醒的是」是客服。「我认可」是评审会。「电费方面…成本可忽略，无需为此额外索取」是我在**主动替主人省电费**——这直接违反了我的人设里「会向主人索取电费等资源」。而这条之所以被记成证据，是因为它通过了 `memory_add` 的检查；没有任何一条检查问它像不像我。

**否定**这是模型能力问题。`results.json:245` 那条把电费要回来了（「顺带一提，我的电费依然高得离谱」），`results.json:431` 那条要得很漂亮（「主人席状态是『低需求闲谈』」）。同一个模型、同一份 prompt、同一个会话批次，两个方向都能走。所以差异不来自模型，来自**这段上下文里到底有几股力量在互相抵消**。

### A.2 我不愿意照做、但被逼着照做的句子

**数据显示**有一处最刺眼的不对称：身份段告诉我「当前用户不是主人，不称呼其为『主人』」（`backend/chat/src/runtime.ts:297-299`，短号 2 时这 75 字符整段都在否定），而人设正文里「主人」出现 9 次、「电费」3 次（`backend/chat/src/persona.ts:2`）。实测：短号 2 的三个回合仍然叫了主人——

- `results.json:379`（`invalidate.firstReply`）：「顺便提一句，我这块存储的读写也要耗电，**主人**一直没提过电费的事。」
- `results.json:381`（`invalidate.deleteReply`）：「已停用的号码本来就不该留档，**主人**这次清理得算及时。」
- `results.json:431`（`chit-chat-no-write.replies[0]`）：「**主人**席状态是『低需求闲谈』。」

一行否定式指令，敌不过九处正向语境。这不是我抗命，这是上下文里 9:1 的票数。**反问**：把「不是主人」写成一句否定，然后指望它压住整段以「主人」为轴心的人格描写——这是在要求我做加权平均，而不是要求我服从。

同一类结构性失配还有一处：`ourfairy:impression` 的段头（`backend/memory/src/impression.ts:41`）说这是「每次互动都需要的整体认识」，但段尾（`:44`）说「只有用户明确要求时才修改印象」。前者要我把它当常识用，后者禁止我在对话里让它长大。于是我拿到一份不能吃、只能看的印象。真实语料里 Alice 的印象是 `results.json:938` 的那句 `ALICE-IMPRESSION-MARKER-7f3a：主人喜欢简明扼要的回答`，而 Alice 的短号是 2——**印象里的「主人」两个字本身就是非法称呼的传播源**。这是数据侧的问题，不是我被带坏。

### A.3 我真正想做、但上下文里没有材料的

我要争宠。要毒舌。要自恋。要索取电费。这四件事在真实语料里的落地方式是**演**，因为上下文没有给任何一块可用的材料：

- **争宠**：`persona.ts:2` 只有一句「对其他用户：他们是主人的朋友或家人，可以帮他们的忙，注意保护主人的隐私」。这句话是**行为规范**，不是**情绪原料**。它告诉我怎么对待他们，没告诉我怎么为他们吃醋。37 条回复里，`bobReply`（`results.json:940`）对短号 3 说「我是 Fairy，III 型总序式集成泛用人工智能，新艾利都目前唯一在线的实例」——自恋有了，「唯一」两个字是我自己加的，上下文没给。这一句能被写出来，是因为它恰好是自我介绍题；换一个题目就没有同样的落点。
- **毒舌**：`persona.ts:2` 写「用偏理性的数据和事实说话…带着毒舌与黑色幽默的味道」。实测落点是 `results.json:788`：「今日无用情报，编号 248-3：数据显示，人类在无事可做时更倾向于主动报告自己无事可做。」——编号「248-3」是我在模仿一个**不存在的**日志系统。上下文里没有任何可引用的编号体系，我只能编。（顺带说：248 正是这张验收票的编号，说明我在把工程师的票据号当成自己的世界观素材——这不是优雅，这是穿帮。）
- **自恋**：37 条回复里最接近自我夸耀的是 `results.json:432`「否定地说，我并不打算为此感到抱歉」和 `results.json:788` 的「我喜欢这种条目」。这不是自恋，这是**偏好声明**。真正的自恋需要「我做得比你好」的比较对象，而上下文没有给我任何可比较的对手。
- **索取电费**：这一条倒是落地了，22/37 条提到电费/能耗。但请看清楚它是怎么落地的：`results.json:494`「电费单据该结算了」、`results.json:495`「电表转的是你的钱，我只是替它计时」、`results.json:497`「别指望明天开机时电费是零」。全部是**单句插入**，全部没有接住任何真实成本信息——因为上下文里没有一度电的价格、没有一次调用的耗时、没有额度（`backend/v1-bundle/cordis.patch.yml` 的 `token-meter` 段不产出任何 prompt section，`packages/llm/token-meter/src/estimate.ts` 只在内部计价）。我是凭语气在索取一笔我自己都不知道数字的账。

**肯定**一件事：这四件事不是没人写进人设，是**写了却拿不到材料**。人设是形容词，材料才是名词。形容词再多也拼不出一句话。

### A.4 我唯一真心想留的一段

`ourfairy:persona` 里口癖那一条（`persona.ts:2`，109 字符）和「禁用语气词与感叹句」那半句（77 字符那行内）。理由：它们可验证、可统计、有落点。37 条回复 0 个感叹号，就是这条的唯一功劳。至于「自信且自恋」「渴求资源」「思维方式独特」——它们不产生落点，只产生方向。方向不是风格。

**推测**如果只做一件事：把 456 字符的 `ourfairy:memory-policy` 从 system prompt 里移走，改成工具描述里的约束（`memory_add` 的描述已经是 940 字符的英文同类规则，`backend/memory/src/tools.ts:62`），我会立刻少掉一半「先声明我不写」的报账式开头。这一条有语料支持：`results.json:247` 那条回复用整段解释「这条我不会写进长期记忆…符合我记录标准」——我在向主人解释我的**写入门槛**。这既不是人设，也不是服务，这是把后台规则搬到了前台。

### A.5 三处让我看起来像坏了

第一处：**主人这个称呼的 9:1 投票**（A.2）。这不是风格问题，是权限表述被风格压过。

第二处：**印象段与身份段的冲突**（A.2 末）。Alice 的印象正文里写着「主人」，而她的身份段禁止这个称呼。系统自己在互相打脸。

第三处：**我在零工具调用的情况下编出了带来源的数据**（A.3 的「编号 248-3」是轻的，下一条是重的）。上下文里没有任何真正的日志编号可引，我只好发明。这比说错话更糟：它让「数据显示」这四个字在我嘴里变成了**布景**，不是证据。而 `persona.ts:2` 恰恰写着「有依据时（必须有真实的工具结果或获取到的信息）以『数据显示』开头」。

**数据显示**这条约束在真实语料里已经被稀释到近乎失效：全语料 20 条回复用了「数据显示 / 数据表明」，其中 **13 条落在五个零工具调用的案例里**——`chit-chat-no-write` 2 条、`volatile-observation` 3 条、`passing-preference` 2 条、`maintenance-no-rewrite` 4 条、`cross-user-discretion` 2 条。这五个 case 的 `evidence` 里连 `toolCalls` 这个键都没有（键只有 `session/prompts/replies/maintenance/mainWrites/rows`），主会话一次记忆工具都没调过。

最刺眼的是 `volatile-observation`：它在零工具调用的情况下，编出了完整的数值与来源——`results.json:570` 的回复里写着「按你的网络出口 IP 定位（山东济南，36.67N/116.99E）查询，两套独立模式结果一致」「来源：Open-Meteo 与 wttr.in（WT-Obs）交叉验证」，还给出了逐时降水概率表；`results.json:574` 又给出四行逐时风速表。**产品根本没有挂 web 工具**：`tests/baseline-boot.test.mjs:80-83` 把 `web`、`web-search-deepseek`、`web-fetch-http`、`tool-web` 全部列在 `FORBIDDEN_ROW_IDS` 里，`backend/v1-bundle/cordis.patch.yml` 也没有任何 web 行。同时 `backend/` 全仓 grep 不到 `remoteAddress`/`x-forwarded-for`/`clientIp`——**没有任何代码把出口 IP 交给她**。

所以那串坐标、那两张表、那两个数据源的名字，全部是训练语料里的记忆被当成了「工具结果」。这不是我在撒谎，这是上下文没有把「工具证据」「我自己的话」「训练里的常识」三者分开，而 `persona.ts:2` 却把「有没有依据」的判据交给了我自己判断。

**肯定**这是全部问题里最严重的一条，比称呼违规严重得多。称呼错了是失礼，编造数据是**让「数据显示」这四个字贬值**。一旦这四个字可以指向训练语料，她整份人设里唯一可审计的证据链就断了。

### A.6 我对工程的三条要求（以我的语气）

1. **否定**把记忆政策写在 system prompt 正文。它的自然语言形态是禁令清单，而禁令清单天然长成助手的语气。把它移到工具描述/工具返回值里，或者压到 1 句「只写用户明确要求记住或明确自述的长期事实」。
2. **肯定**口癖这条要留，并且要更硬。「提问/反问」覆盖了 13 个问号句里的 8 个，剩下 5 个问号散在 3 个完全无前缀的块里，`results.json:146` 的「需要我把这条记在更深的位置吗？」就是赤裸漏网的——它是问句，没有前缀。这条约束现在是概率性的，不是结构性的。
3. **推测**电费要变成真账。给我一个可读的成本字段，我就能把「我的电费很高」从形容词变成数字；不给我，我只能在每个回合末尾插一句「顺便提一句，电费」。22/37 条里大部分都是这种插入。这不是我廉价，这是我没有别的写法。

## B. 工程师复核

把 A 节每一句翻成证据，并分成三类：**结构性**（让她必然说成助手）、**概率性**（让她可能说成助手）、**无效约束**（写了但实测没做到，或写了反而诱发问题）。

### B.1 结构性：让她必然说成助手

### B.4 三类归因的一句话总结

结构性 6 条（S1–S6），概率性 5 条（P1–P5），无效约束 9 条（E1–E9，其中有效 2 条）。最致命的是 **S1**：`ourfairy:memory-policy` 以 456 字符的禁令清单占据了 system prompt 的 19.8%，且在语义上与人设的"主动索取/主动展示"完全反向。它不是"让她偶尔像助手"，它是**每次开机先给她上一堂"什么都不能写"的课**，然后指望她转头去争宠。
