# T16：真实硅基账号与手机 WAV 最小场景（交 T21/T22）

本票只完成真实 profile → HTTP → 硅基平台替身、Android 状态/HTTP 替身与编译。
尚未执行真实硅基账号或 vivo 麦克风；没有用合成静音冒充真实录音识别证据。

1. 在后端部署环境提供 `VOICE_API_KEY`（不要粘到票面、手机设置或日志）。
   确认 `OURFAIRY_ASR_MODEL` 采用该账号支持的型号，例如当前部署默认
   `FunAudioLLM/SenseVoiceSmall`，`OURFAIRY_ASR_ENDPOINT` 是硅基真实地址。
   通过 `npm run backend:start -- --json` 启动真实产品 profile。
2. 构建/安装使用该后端地址的 APK：Gradle 参数
   `-Pourfairy.identityEndpoint=<已部署后端地址>`。手机登录受邀账号，进入会话，
   先输入“原草稿”。允许麦克风，点击“语音输入”，说“今天下午三点提醒我喝水”，
   点击“结束录音并转写”。
3. 预期：16kHz mono PCM16 WAV 被真实硅基账号接受；草稿成为
   “原草稿”加识别文字，仍可编辑。没有新聊天消息/Agent 运行/录音附件。
   用户编辑并亲自发送后才产生聊天输入。记录实际型号、账号接受容器、HTTP
   状态、返回文字、录音长度和手机型号；日志不包含密钥/登录 token。
4. 再录音一次，分别在录音时取消、转写时取消、转写时切会话/退出账号。
   预期旧草稿保留或跟随既有会话切换规则清空；迟到结果不写入新会话草稿，
   取消停止麦克风与一次性 ASR 请求，不停止已接纳的聊天推理。
5. 设备设置拒绝麦克风后再尝试：明确权限提示、原草稿保留。
   在隔离部署移除 VOICE_API_KEY，重启后再尝试：明确不可用、无成功文字。

Firebase 配置沿用本机已有假 key 桩，仅用于编译；不能据此宣称真实
Firebase/Crashlytics 工作。本场景需要真实 APK/麦克风和硅基凭据，构建与
替身通过均不替代这个验收。
