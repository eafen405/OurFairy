## 原标题

会话标题：自动生成、兜底与老会话兼容

## 原正文

## Parent

#250（会话管理能力缺失）。本票覆盖其中第 1 项「根据第一次对话内容起标题」与老会话的兼容。

## What to build

会话不再以原始 id 呈现。新建会话在收到首条人类消息后立刻有名称：先出现由该条消息派生的确定性兜底标题，随后由模型生成的标题替换它，两种来源在数据上可区分。用户在界面上看到的是标题，不是 `会话 N` 加一串 id。

历史会话要兼容，但不能为此反复付出模型调用：列表为没有标题的老会话，从它的首条人类消息派生一个可读名称，这一步只读、不写会话日志、不调用模型。用户第一次打开该会话时，才补生成一次模型标题并持久化；此后每次进入都只读那个已落库的标题。

模型标题生成失败不是需要用户处理的异常：保留已有标题即可，不重试、不弹错、不阻塞回复。

标题止于列表与标题栏，不进入模型可见的对话内容。

## Acceptance criteria

- [ ] 新会话在首条人类消息后，列表显示由该消息派生的标题；模型标题到达后，列表与该会话的标题栏都更新为模型标题
- [ ] 标题来源可区分（兜底 / 模型 / 用户），用户的标题不会被自动生成覆盖
- [ ] 没有标题事件的历史会话，在列表中显示从其首条用户消息派生的可读名称；这条展示路径不写会话日志、不调用模型
- [ ] 历史会话首次打开时补生成一次模型标题并持久化；再次进入不重复生成、不产生新的模型请求
- [ ] 模型标题生成失败时保留已有标题，不重试、不阻塞回复、不影响列表可用
- [ ] 兜底标题与模型标题受同一长度上限约束，超长按 UTF-8 边界截断，规范化为空时不落库
- [ ] 会话列表对每个会话返回标题，客户端抽屉显示标题而非序号与裸 id
- [ ] 标题是仅日志的会话事实，不出现在模型可见的消息内容里
