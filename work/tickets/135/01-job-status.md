# 01: 任务状态词表：未知状态显式化，并与原生类型对账

## Parent

[#135 原生语义漂移守卫](https://github.com/eafen405/OurFairy/issues/135)

## What to build

原生任务状态是导出类型 `JobStatus = 'running' | 'stopping' | 'completed' | 'killed' | 'failed'`
（pinned dsh），产品现在用一张手写表翻译成数字。上游新增状态时，查表得到 `undefined`：可用任务
的状态会以缺失字段的形式漏进投影，活动摘要可能把仍在执行的任务报告成安静；不可用任务被折成
0（未知），终态任务永远不收敛。整个过程没有报错。

本票让未知状态在运行期显式化，并让上游词表变化在测试期响亮失败：

- 任何无法映射的原生状态都报告为数字 `0`（未知），绝不返回 `undefined`，也绝不猜测成终态。
- 活动摘要把未知当作「不可收敛」（活动状态 0），而不是「非终态」（活动状态 2）或安静（1）。
- 新增一条测试期对账：读取 pinned dsh 中 `JobStatus` 的导出类型声明，与产品映射集合逐项比较；
  上游增删成员时测试失败并指出成员名。不得把原生成员抄成第二份字面量清单。
- `/chat/jobs/output` 返回的任务状态同样经过这一映射，未知时是 0。

已知状态保持现有数字与终态收敛行为；既有测试不得改写期望来迁就实现。

## Acceptance criteria

- [ ] 可用任务的原生状态不在映射内时，投影与 `/chat/jobs/output` 的状态是 `0`（字段存在），不是 `undefined`，也不是终态
- [ ] 该会话的活动摘要是 `0`（未知），不是 `1`（安静）；不可用且状态未知的任务同样保持 `0`
- [ ] 已知五种状态仍分别映射为 1/2/3/4/5，终态任务仍收敛，既有用例不变
- [ ] 新增测试 `native job status vocabulary matches the projection`：从 pinned dsh 的 `JobStatus` 声明读取成员集合，与产品映射的键集合比较；多一个或少一个都失败并指出成员名
- [ ] 该测试不把原生状态抄成第二份字面量清单；它读取的是类型声明本身
- [ ] 提交说明写明：上游增删 `JobStatus` 成员时，失败的是哪一条断言
