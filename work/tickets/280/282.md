## What to build

用户在自己的会话里让 Fairy 把文字投递给「自己」时，这段文字落在发起投递的那个会话，并在该会话里表现为一条普通 Fairy 消息；投递给其他用户时仍落在对方主会话。发起会话已归档、或调用方没有可用的发起会话（未来的后台投递，例如自动触发的周报）时回落主会话。回执里的会话 id 就是实际落点。

本次新增的唯一接口面是会话服务的一个布尔读：这个会话能否作为投递落点（存在、属于该发送者、未归档）。落点判定集中在一处，投递、恢复（记录里的落点）与通知都读同一个结果。

## Acceptance criteria

- [ ] 在会话 A 里让 Fairy 把文字投递给本人，文字出现在 A（一条普通 Fairy 消息），不在主会话。
- [ ] 投递给其他用户，仍落在对方主会话。
- [ ] 发起会话已归档时，自投回落到主会话。
- [ ] 落点判定只在一处：投递行给出目标，事件、回执与后续通知读同一结果；不新增显式目标会话参数。
- [ ] 会话服务新增且只新增一个布尔读（存在 + 属于发送者 + 未归档），归档事实经窄读取得，不枚举归档列表。
- [ ] 落点判定抽成 delivery 行内部的纯函数并有单元测试，覆盖「没有发起会话 / 发起会话不属于发送者」输入；该输入今天不可经工具到达，为未来后台投递保留。
- [ ] 工具描述、`GLOSSARY.md`（主会话、投递消息）、delivery / sessions / chat 的 README 与主会话归档注释与新规则一致。
- [ ] 行为测试经真实启动器与现有会话/聊天路由，不新增测试接缝。
