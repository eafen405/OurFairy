# #280 自投落点跟随发起会话：投递给本人时落在当前会话

- GitHub：<https://github.com/eafen405/OurFairy/issues/280>
- 状态：OPEN

## 原标题

自投落点跟随发起会话：投递给本人时落在当前会话

## 原正文

## Problem Statement

用户在自己的会话里让 Fairy 把文字或文件投递给「自己」时，投递总是落在自己的主会话。用户当时正在会话 A，要拿到东西必须先离开 A、回到主会话去翻；主会话本来是为「其他用户能有一个稳定落点」而存在的定位概念，被复用到自投场景后，反而增加了寻找成本。

## Solution

Fairy 投递给收件人本人时，落在**发起投递的那个会话**；投递给其他用户时仍落在对方主会话；发起会话不可用（已归档）或没有发起会话（记忆维护子、后台行为）时回落主会话。通知跟随投递落点，而不是固定指向主会话。

## User Stories

1. 作为代理人，我在新会话里让 Fairy 给我一份文件，我希望文件出现在这个会话里，这样我不必切到主会话去找。
2. 作为代理人，我在会话里让 Fairy 给我一张图片，我希望它和这条对话放在一起，而不是出现在另一个会话。
3. 作为代理人，我希望投递给我的文字和文件一起落在同一个会话，不被拆到两处。
4. 作为代理人，我让 Fairy 给**另一个**代理人投递文件时，它仍应落在对方主会话，因为对方可能根本没有打开任何会话。
5. 作为代理人，我把自己已经归档的会话当作发起会话时，我希望投递回落到主会话，因为归档会话在列表里看不见，东西会丢在视野外。
6. 作为代理人，Fairy 在没有具体会话的情况下主动投递给我时，我希望它落主会话，因为那是我唯一稳定的落点。
7. 作为代理人，我收到投递后看到的通知应该指向文件真正所在的会话，点开就能看见它。
8. 作为代理人，我在主会话里让 Fairy 给自己投递时，行为与现在一致（落主会话），我不需要学习新例外。
9. 作为代理人，同一次投递因网络或重启重试时，我希望它只出现一次，且仍在第一次决定的那个会话。
10. 作为代理人，我在会话 A 里投递给自己后，从主会话取不到这份文件，这是预期的：它在 A 里。
11. 作为代理人，我在会话 A 里投递给自己后，把 A 归档，文件随会话一起归档，不额外复制到主会话。
12. 作为投递的模型侧调用者，我需要知道回执里的会话就是实际落点，以便后续引用它。
13. 作为维护者，我希望落点规则只在一处判定，投递、恢复与通知都读同一个结果。
14. 作为维护者，我不希望为这件事引入「指定任意目标会话」的新参数或新概念。

## Implementation Decisions

- **目标解析规则**：收件人短号等于发送者短号，且发起会话存在、属于该发送者、未归档 → 目标是发起会话；其余情况目标是收件人主会话。判定只使用已有事实：工具执行上下文里的发起会话、会话 header 的归属、归档事实。
- **归档事实需要一个窄读法**：会话服务目前只提供读、列、主会话、创建、归档、恢复；投递需要一个「这个会话能否作为投递落点」的布尔读，而不是枚举或全量列表。这是本次唯一新增的接口面。
- **幂等与重试**：投递身份仍由「发起会话 + 调用 id」派生。重试命中已有记录时使用记录里的落点，不重算；落点不参与「同身份但内容或收件人不同」的冲突判定。
- **恢复**：启动时结算未完成的投递沿用记录里的落点，因此不新增恢复规则。
- **回执**：回执里的会话 id 就是实际落点，不新增字段、不改形状。
- **通知**：Android 侧把「整账号积压只发一条、优先主会话」改为「按落点会话发通知」，点击仍按会话深链；前台不发的规则不变。
- **术语**：主会话的定义拆成「通知落点 + 跨用户投递落点」两件事；投递消息的定义改为「送到收件方的会话：本人取发起会话，其他用户取其主会话」。归档拒绝主会话的理由保持不变，因为跨用户投递仍落主会话。
- **不改**：不新增显式目标会话参数；不迁移历史投递记录；界面不区分「投递」与「普通回复」——投递消息在收件会话里本来就是一条普通 Fairy 消息。

## Testing Decisions

- **好测试的样子**：只断言外部行为——经真实后端启动器发出投递，读收件方的投影与下载接口，不检查内部函数、不窥探数据库行。
- **接缝**：沿用现有投递行为测试所用的那个接缝（真实启动器 + 会话/聊天/附件路由），不新增接缝。
- **覆盖**：
  - 自投落发起会话（文字一例、文件一例），并从该会话下载成功。
  - 自投的发起会话已归档 → 回落主会话。
  - 无发起会话的投递（创建者不是用户会话）→ 回落主会话。
  - 投给其他用户 → 仍落对方主会话。
  - 同一次调用重试 → 只有一条、仍在同一会话。
  - 落点会话可下载，其他会话取同一附件 404。
- **客户端**：通知选择的单元测试，沿用现有 Robolectric 与 Compose 测试设施，不新增 instrumentation 接缝。
- **收口**：按改动面跑相关测试；最终跑 `npm test`、`npm run combo:verify`、Android `test lintDebug`。

## Out of Scope

- 历史投递记录迁移；显式指定目标会话的参数；跨用户投递到非主会话；投递与回复在界面上的区分；归档语义变化；投递重试策略变化。
