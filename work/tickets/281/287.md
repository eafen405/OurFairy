## What to build

点会话里的一条图片附件，它直接在应用内全屏打开、可双指缩放，不需要先选保存位置；预览里保存图片不再重新下载。同时把「点附件该做什么」收成唯一一处判定：一个纯函数，输入附件的 MIME 与文件名，得到四种去处之一——图片预览、文本预览、外派系统应用、另存为。上传的 MIME 常回落为 `application/octet-stream`，此时按后缀判断；有可信 MIME 时以 MIME 为准，只有 `octet-stream` 或缺失才由后缀纠正。

附件字节仍按会话鉴权走现有下载接口，先落到应用缓存的附件专用子目录；同一附件（会话 + 消息 + 序号）重复打开复用同一路径，不产生第二份字节；预览与保存共用同一份字节；关闭预览后清理该缓存文件，已另存的文件不受影响。本票只做图片这一条真实去处：文本、PDF/Office 暂时沿用现在的另存为，由后续票逐个替换，因此本票单独可交付、不出现回退。

## Acceptance criteria

- [ ] 点图片附件直接进入应用内全屏并可缩放；预览里保存能拿到字节，且整次打开只下载一次。
- [ ] 同一会话消息的同一附件重复点开复用同一缓存路径与字节；不同会话/消息/序号不会相撞。
- [ ] 去处判定只在一处纯函数：图片、文本、外派、另存为四选一，卡片与打开流程都不各自猜类型。
- [ ] 该纯函数有单元测试，覆盖 `.md`（`text/markdown` 与 `octet-stream` 两种 MIME）、`.txt`、代码后缀、图片、`.pdf`、`.docx`、未知类型、大写后缀、无后缀、`octet-stream` 被后缀纠正。
- [ ] 非图片附件在本票里行为与今天一致（另存为）。
- [ ] 关闭预览后回到刚才那条消息的位置，会话不跳。
- [ ] 应用内打开不需要额外的存储权限。
- [ ] 客户端词汇表与 README 记录「附件去处」与附件缓存子目录的用途；声称须有可执行检查对应。
