## What to build

点 Markdown 附件看到排版后的内容，而不是原始符号；点纯文本与常见代码文件看到等宽、只读、保留换行与缩进的全文。两者都在应用内预览，不再先另存为。文本按 UTF-8 解码，失败再试 GB18030；两种都解不出时明确提示「无法解码」，不显示乱码。超过 2 MiB 的文本不在应用内展开，改走外派（由后续票提供），没有可外派的应用时回落另存为。复用上票的附件缓存与单次下载：预览用的就是那份字节。

## Acceptance criteria

- [ ] `.md`（`text/markdown`，或 `octet-stream` 时按后缀判定）打开后呈现渲染排版。
- [ ] `.txt` 与代码后缀以等宽只读视图显示，换行与缩进保留。
- [ ] 中文 UTF-8 与 GB18030 编码的文本都能正确显示；两者都不成立时给出明确提示而非乱码。
- [ ] 超过 2 MiB 的文本不在应用内展开，走外派/另存为。
- [ ] 解码与文本大小规则有不依赖 UI 的测试；「点击附件 → 进入文本预览」有 Robolectric/Compose 覆盖。
- [ ] 不新增解析或渲染依赖。
- [ ] 客户端词汇表与 README 记录文本预览的边界（只读、2 MiB、编码顺序）。
