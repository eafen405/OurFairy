# #281 会话内附件打开：md/txt 应用内预览，PDF/Office 外派系统应用

- GitHub：<https://github.com/eafen405/OurFairy/issues/281>
- 状态：OPEN

## 原标题

会话内附件打开：md/txt 应用内预览，PDF/Office 外派系统应用

## 原正文

## Problem Statement

会话里的附件点下去只有「另存为」：先选保存位置、再离开应用去文件管理器找。用户想看一张图或一份 Markdown/文本，必须完整走一遍下载。界面上图片和文档还是同一个通用文件条，不区分类型、没有缩略图。

## Solution

点附件直接打开：图片在应用内全屏缩放并可保存，Markdown 按排版渲染，纯文本与常见代码文件以只读方式显示。PDF 与 Office 文档交给手机系统里已安装的应用打开（外派，不是下载）。没有能打开它的应用、或类型不认识时，回落到现在的另存为。

## User Stories

1. 作为代理人，我点会话里的图片，希望立刻全屏看到并双指缩放，而不是先选保存位置。
2. 作为代理人，我希望在预览里就能保存这张图，不必为了保存退出预览。
3. 作为代理人，我点 Markdown 附件，希望看到渲染后的排版，而不是原始符号。
4. 作为代理人，我点纯文本附件，希望直接读到内容，并保留换行与缩进。
5. 作为代理人，我点代码文件，希望它等宽显示、可读。
6. 作为代理人，我点 PDF，希望手机系统里能看 PDF 的应用直接打开它，而不是先落到下载目录。
7. 作为代理人，我点 docx，希望同样由系统里已安装的应用打开。
8. 作为代理人，我设备上没有能打开这个 PDF 或 docx 的应用时，希望它仍能另存为，而不是点了没反应。
9. 作为代理人，我打开中文文本时，希望不会看到满屏乱码。
10. 作为代理人，我点一个很大的文本文件时，希望要么明确告诉我不在应用内展开，要么就流畅打开，不要卡住界面。
11. 作为代理人，我打开附件时希望只下载一次，预览和保存共用同一份字节。
12. 作为代理人，我关闭预览后希望回到刚才那条消息的位置，会话不跳。
13. 作为代理人，我收到的投递附件与我上传的附件，点开的行为应当一致。
14. 作为代理人，我希望打开附件不需要我额外授予存储权限。
15. 作为维护者，我希望「点下去该做什么」只在一个地方判断，各组件不各自猜类型。

## Implementation Decisions

- **类型路由是唯一分叉点**：一个纯函数，输入附件 MIME 与文件名，输出四种去处之一——图片预览、文本预览、外派系统应用、另存为。卡片、预览页与下载器都不做各自判断。
- **MIME 可信度规则**：上传时的 MIME 来自系统 `ContentResolver`，常见回落是 `application/octet-stream`。因此 MIME 为 `octet-stream` 或缺失时**按后缀判定**（`.md`、`.txt`、`.kt`、`.ts`、`.json`、`.yaml`、`.csv` 等），否则以 MIME 为准。
- **字节来源复用现有下载接口**：仍按会话鉴权取字节，先落到应用缓存的专用子目录，再交给预览或外派。保存复用同一份字节，不二次下载；预览结束清理缓存文件，已保存的文件不受影响。
- **图片**：复用现有全屏图片查看组件（缩放、翻页、保存），入参为本地路径；不为附件另写查看器。
- **文本**：Markdown 复用现有渲染；纯文本与代码用等宽只读视图。解码顺序为 UTF-8 → GB18030 → 失败则明确提示「无法解码」，不静默显示乱码。
- **文本大小上限**：超过 2 MiB 的文本不在应用内展开，直接走外派/另存为，避免一次性读入卡住界面。
- **外派**：把 FileProvider 的暴露面从「安装包目录」扩到「附件预览缓存子目录」（不是整个 cache），用 `ACTION_VIEW` + chooser；没有匹配的应用时回落到另存为。上游 rikkahub 有一个 `openLocalFile` 助手正是这个形状，可以按它的思路重写，但暴露面按我们的收窄做法只开子目录。
- **不引入任何新依赖**：PDF 与 Office 都不在应用内渲染，没有新库、没有服务端转换。
- **不做**：缩略图；PDF/Office 应用内渲染；服务端转换；音视频；草稿区预览。

## Testing Decisions

- **好测试的样子**：只断言外部行为——给定 MIME 与文件名，得到哪种去处；不测 composable 内部结构，也不测平台 Intent 本身。
- **接缝一（本次唯一新增）**：类型路由纯函数。用例覆盖：`.md`（text/markdown 与 octet-stream 两种 MIME）、`.txt`、代码后缀、`.png`/`image/jpeg`、`.pdf`、`.docx`、未知类型、后缀大写、无后缀、MIME 与后缀冲突时以后缀纠正 octet-stream。
- **接缝二（沿用现有）**：现有 Robolectric 与 Compose 测试设施，覆盖「点击附件 → 选中去处」与缓存文件名仍只由 `(session, message, index)` 决定。
- **文本解码**：UTF-8 与 GB18030 各一例，含一段中文；解码失败返回明确状态而非异常。
- **手动验收**：真机各打开一次图片、Markdown、txt、PDF、docx，并验证「未安装对应阅读器」的回落；当前无设备时记为未执行，不以模拟器替代。
- **收口**：Android `test lintDebug assembleDebug`。

## Out of Scope

- PDF 与 Office 的应用内渲染；服务端转换；附件缩略图与图片网格；草稿区/上传前预览；音视频；文本预览里的搜索、分页或编辑；对「查看全文」的改动。

## Further Notes

- 上游 rikkahub 的文件点击本来就是「外派到系统应用」，不是下载；我们剪枝时连同 `openLocalFile` 与 FileProvider 的宽暴露面一起删掉了，现在只留安装包目录。这次按需要把暴露面精确开回来。
- 这个范围下没有任何新增依赖：图片复用现有组件，md/txt 复用现有渲染与系统解码，PDF/Office 走平台 Intent。
