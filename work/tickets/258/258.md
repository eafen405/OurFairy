# #258 Android 会话导航：统一会话列表浮层与当前会话事实

- GitHub：<https://github.com/eafen405/OurFairy/issues/258>
- 状态：OPEN

## 原标题

Android 会话导航：统一会话列表浮层与当前会话事实

## 原正文

## Problem Statement

控制台与会话页目前用两种拓扑打开同一份会话列表：会话页直接打开抽屉，控制台却先进入一个会话编号为空的假页面，再由该页面打开抽屉。抽屉背后还可能显示“会话不可用”，让用户在正常使用路径上穿过错误状态。

当前会话也有不一致的呈现：控制台显示后端 opaque id，抽屉和标题栏显示会话标题。归档当前会话后，页面还需要自己记住它是否曾经存在，并推断应该跟随哪个会话。页面因此理解了本应由会话状态拥有的选择与归档规则。

## Solution

会话列表只保留一种拓扑：它是控制台与对话页共用的会话列表浮层，不再伪装成独立目的地。删除会话列表假目的地及其错误底页。

当前会话由单一事实来源提供编号与标题，控制台、抽屉和标题栏都显示同一份会话标题。归档后的跟随规则由会话状态 module 拥有，页面只响应明确的选择结果。

## User Stories

1. 作为用户，我希望从控制台点击“全部会话”就直接看到会话列表，以便不必经过一个过渡假页面。
2. 作为用户，我希望从对话页打开的会话列表与控制台相同，以便形成稳定的使用习惯。
3. 作为用户，我希望打开会话列表时背后不会显示“会话不可用”，以便正常操作不被误认为错误。
4. 作为用户，我希望关闭列表后仍留在原来的控制台或对话页，以便不打断当前上下文。
5. 作为用户，我希望从列表选择会话后进入该会话，以便继续阅读或回复。
6. 作为用户，我希望重复选择当前会话时不会无意义地重建页面，以便保持阅读位置。
7. 作为用户，我希望控制台显示当前会话标题而不是 opaque id，以便识别自己将进入的会话。
8. 作为用户，我希望无标题会话在控制台使用与列表一致的占位名称，以便不会回退显示 opaque id。
9. 作为用户，我希望长会话标题在窄屏和大字体下合理截断，以便主要操作仍然可达。
10. 作为用户，我希望归档当前会话后跟随到产品规定的主会话，以便不会停留在已离开默认列表的目标。
11. 作为用户，我希望过期或无权访问的通知目标仍显示不可用，以便不会被误判成刚刚归档的会话。
12. 作为用户，我希望归档视图、恢复、改名和停止回复等既有列表能力在两个入口保持一致，以便不丢失功能。
13. 作为用户，我希望从对话页返回时仍回到首页，以便保持现有主要返回路径。
14. 作为用户，我希望旧版本留下的会话列表恢复记录不会导致崩溃或错误页，以便升级后仍能正常启动。
15. 作为维护者，我希望会话列表只有一个 module 和一个 seam，以便修改一次即可覆盖两个入口。
16. 作为维护者，我希望当前会话编号与标题来自同一份远程会话事实，以便不在本地建立第二份标题权威。
17. 作为维护者，我希望归档跟随规则具有 locality，以便页面不再复制会话状态机的判断。
18. 作为测试者，我希望从真实用户入口验证列表与归档行为，以便测试覆盖实际拓扑而不是测试专用路由。
19. 作为未来功能接入者，我希望页面目的地与浮层保持区分，以便新模块不会再次把临时界面伪装成页面。

## Implementation Decisions

- 依赖目的地 catalog 规格完成后的单一拓扑定义，删除会话列表目的地及其页面装配、准入和恢复分支，不留下第二份兼容映射。
- 把会话列表浮层提升为控制台与对话页共享的 module；两个入口跨同一 seam 打开、关闭和选择会话，浮层不进入导航返回栈。
- 浮层继续提供现有默认会话、归档视图、恢复、改名、停止回复及首页和设置入口；不另建精简版列表。
- 控制台“全部会话”和无可用会话时的主按钮都打开同一浮层；对话页现有列表入口也改为该 module。
- 删除会话编号为空的对话页用法。对话页只接受真实会话目标，不再用空目标承担列表职责。
- 当前会话沿用最近选择、缺省回退主会话的定义；编号、标题、主会话标记与可选状态由同一份会话快照派生。
- 控制台、浮层和标题栏统一显示会话标题；无标题时沿用现有占位名称，任何位置都不把 opaque id 当作用户可读标题。
- 不在本地另存标题，不根据消息内容重新推断标题，不改变会话标题来源与改名钉住规则。
- 归档当前会话后的跟随规则由会话状态 module 拥有。页面不再维护“曾经存在”的闩锁，也不再自行比较列表消失原因。
- 会话状态必须继续区分“当前会话已归档并选择主会话”与“恢复目标从未可用、过期或不属于当前账号”；后者仍是不可用，不自动跳转。
- 选择另一会话时保持现有替换对话目标的语义；对话页返回仍清回首页，不恢复已经删除的列表假目的地。
- 旧持久化位置若为会话列表，升级后安全回退首页，不自动打开浮层，也不显示错误页；不迁移为新的永久页面状态。
- 主会话归属、会话归属、归档事实、通知定位、提醒和后台接收语义保持不变。

## Testing Decisions

好测试从现有页面与会话状态 seam 断言外部行为：浮层是否出现、标题是否一致、选择落到哪里、归档后跟随哪个会话；不断言私有闩锁、内部路由实现或绘制结构。

- 不新增测试专用导航 seam。沿用 Compose/Robolectric 页面测试驱动控制台与对话页两个真实入口，验证它们打开同一可观察列表行为。
- 沿用会话状态契约测试覆盖当前会话派生、缺省主会话、归档跟随、过期目标和账号切换；页面测试只验证这些结果的导航与呈现。
- 目的地 catalog 的表驱动测试同步验证会话列表目的地已不存在，旧恢复记录回退首页，且没有遗留准入或恢复分支。
- 覆盖控制台有会话与无会话两个入口、对话页入口、关闭浮层、选择当前会话、选择另一会话、归档视图与恢复。
- 覆盖控制台、浮层行和标题栏的标题一致性；无标题占位、长标题、窄屏和大字体不得显示 opaque id。
- 覆盖归档当前会话跟随主会话，同时保留未知或无权会话的不可用行为，避免把两种语义合并。
- 沿用现有会话标题、归档、通知定位和页面导航测试作为先例；删除假目的地后，对应测试改为验证真实浮层路径，不复制旧路由。
- 最终验证覆盖相关 Android 测试、lint 与构建；页面行为、状态契约和真机验收分别报告。

## Out of Scope

- 目的地 catalog 本身的建立；由前置规格完成。
- Fairy 互动、后台接收、提醒记账和会话运行时生命周期改造。
- 会话、主会话、归档、标题与通知定位的后端语义变化。
- 新的会话创建流程、社交群聊、跨用户会话或本地标题副本。
- 统一所有页面外壳、设置分组、视觉主题或返回动画。
- 游戏、Unity、动态插件和后端 dsh 改动。

## Further Notes

- 本规格依赖目的地拓扑规格，实施顺序在其后；依赖关系使用 GitHub 原生 blocked-by 记录。
- 会话列表浮层不是目的地，打开或关闭它不改变冷启动恢复位置。
- 当前会话只是客户端默认呈现与进入目标，不改变主会话接收投递与通知的产品地位。
