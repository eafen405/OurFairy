## What to build

新增独立的电费插件，把「这台 Fairy 花了多少」从会话日志里算出来：遍历全部会话（含无归属的维护与学习子会话），累加每次已结算模型调用的四个 token 桶，按 `Asia/Shanghai` 切成「本日」「本月」「历史以来」，并给出最近 30 天的逐日序列。结果在进程内按会话缓存，以持久化修订号为失效判据。

约束（来自规格，均为已核实事实）：

- 不加账本表，日志是唯一权威。
- 修订号必须逐会话向持久化取，会话列表不携带它。
- 未落盘的会话一律不缓存——它们列表里的修订号在创建时分配、此后不再更新，用它做判据会冻结账目。
- 活跃会话走快照路径，缓存只服务冷会话。
- 没有 `turn/end` 的悬挂回合不计入。
- 按当地时区切日切月，「历史以来」不设起点。

## Acceptance criteria

- [ ] 给定一组会话日志，聚合结果为正确的四桶合计，并按当地日与当地月正确分桶
- [ ] 跨当地日边界与月边界的回合落在正确的一天/一月
- [ ] 重试产生的多个尝试分别计入；同一回合同一事件位置内后来的用量样本替换先前的
- [ ] 供应商未上报用量的调用不计入，且不使整体结果变成失败
- [ ] 悬挂回合（无 `turn/end`）不计入
- [ ] 只有子会话、没有用户会话时仍然给出正确合计
- [ ] 日志修订号未变时复用缓存、不再读日志；修订号变化时重读
- [ ] 未落盘会话不进入缓存
- [ ] 空会话集合给出全零结果而不是失败
- [ ] 首次聚合的代价以会话数与日志总字节为函数被测试固定，不留下无依据的「可接受」断言
