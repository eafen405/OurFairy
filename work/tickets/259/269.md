## What to build

提醒聚合直接按账号和会话键读取持久记录，活运行时不再是发现欠账的必要条件。进程恢复后没有活运行时也能按既有规则结算提醒，同时保留合并提醒、主会话优先、预览与发布失败语义。

## Acceptance criteria

- [ ] 提醒欠账从持久 ChatSyncRecord 读取，不通过遍历活运行时获得；不增加第二份提醒或活动权威。
- [ ] 只有持久记录、没有活运行时时仍能结算欠账，并使用既有通用预览兜底。
- [ ] 有本次观察内容时，提醒预览仍按 seq 选择最新 Fairy 输出，而不是按呈现位置选择。
- [ ] 多个会话错开恢复时只发布一条合并提醒，未完成恢复的会话不会被误判为已结算。
- [ ] 合并提醒继续优先定位主会话，前台或关闭后台接收时保持抑制行为。
- [ ] 领取、消费与平台发布顺序保持不变；发布失败可以损失一次声音，但不得重放旧 episode。
- [ ] 账号切换、退出登录、归档和迟到结果保持隔离，停止观察不停止后端 Agent。
- [ ] 现有观察集合、标题刷新、选中会话共享运行时和按行停止回复行为不变。
- [ ] 不新增提醒正文字段、消息正文持久化、数据库 schema 或后端接口。
- [ ] 现有生产 RemoteReceiveState seam 的行为测试覆盖以上路径，相关 Android 测试、lint 与构建通过。
