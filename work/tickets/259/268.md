## What to build

在现有 presentation benchmark 中增加可重复的多会话组合负载，让多个带历史会话与至少一个持续流式会话同时运行。维护者可以测量连接、内存和呈现延迟，不再只靠单会话结果推断多会话成本。

## Acceptance criteria

- [ ] 组合负载固定会话数、每会话历史、流式正文长度、片段大小与间隔，并可从干净检出重复运行。
- [ ] 测量使用生产接收与呈现路径及可重放合成后端，不建立第二套会话聚合模型。
- [ ] 输出连接数、堆内存、接收至状态、接收至帧、刷新预算与主线程相关指标，能判断最新版本是否已应用并呈现。
- [ ] 多会话结果与 #74 的单会话五档负载分开命名、记录和比较，不混入旧基线。
- [ ] 同一设备、同一构建至少重复三轮，记录设备条件、构建 SHA、负载参数、异常样本和实际命令。
- [ ] 模拟器、主机或 Debug 数据只标记为方向性参考；无目标设备时明确保留基线缺口，不声称性能达标。
- [ ] 不修改单会话合并、排序、呈现行或滚动实现，也不进行连接和调度优化。
