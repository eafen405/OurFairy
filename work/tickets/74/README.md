# #74 拆分草案：Android 长回复呈现性能

父票：[#74](https://github.com/eafen405/OurFairy/issues/74)。本目录是 `to-tickets` 的草案，发布前不创建 GitHub issue。

## 现状核对（2026-10-19）

- #42 已交付：五档固定负载、`scripts/measure-presentation.py`、release 内的
  `PresentationBenchmarkActivity`、host 解析基线测试，均已入库（`cee4098c`、`6861fc3`）。
- 但入口不满足本票要求：Activity 直接构造 `RemoteChatMessage`，**没有经过生产接收状态**
  `RemoteChatState`；默认负载（流式 20,000 字符、32 字符/片）与 #42 证据记录的
  （232,703 字符、128 字符/20 ms）不一致；结果没有"最新快照是否已应用并呈现"的明确字段。
- 主检出里有一批**未提交**的 `frontend-v1` 模块裁剪改造（删 `ai/`、`web/`、`document/` 等模块），
  与本票无关（#74 明确把客户端迁移/视觉改造列为范围外）。本票只从中取用与本票直接相关的
  benchmark 源集思路，不纳入该改造。

## 拟议票（垂直切片，按依赖顺序）

1. **测量入口入库并可干净构建** — 阻塞于：无
   - 交付：`benchmark` 源集 + 固定负载资产 + 与 release 同优化/同签名的 benchmark 构建变体；
     干净检出执行 `:app:assembleBenchmark` 产出可安装 APK；host 基线测试指向实际存在的样本位置。
   - 验收：产物 SHA/签名可记录；产品 release APK 不再携带测量代码；样本与源码在版本控制中。

2. **五档负载唯一化并驱动生产接收状态** — 阻塞于：1
   - 交付：一份权威参数（消息数、正文字符数、片段大小与间隔、历史条数）写入入口与文档；
     可重放合成后端经生产 `RemoteChatState` → `RemoteTranscript` 跑五档负载；参数出现在结果 JSON。
   - 验收：流式/突发参数与 #42 记录一致或明确换版；结果可复现；既有呈现行为测试全绿。

3. **结果回答"最新快照是否已应用并呈现"** — 阻塞于：2
   - 交付：received/observed/superseded/最新版本是否已应用、终态格式呈现延迟、分阶段耗时；
     脚本采集设备身份、`gfxinfo framestats`、`meminfo`。
   - 验收：一次运行即可判定是否积压；无法判定时明确报错而不是报 0。

4. **固定配置模拟器三轮基线（方向性）** — 阻塞于：3
   - 交付：同一模拟器配置、同一 APK、五档各 ≥3 轮的基线；每轮记录设备/系统/刷新率/字体/构建 SHA/
     签名/负载参数；写入证据目录并标注"模拟器方向性参考，不是 vivo S50 结论"；门槛与原始数据交 #45。
   - 验收：数字可复跑；缺真机的条件与未完成项逐条记录。

5. **热点判定与受控优化** — 阻塞于：4
   - 交付：按问题判据判定是否命中；命中则把热点定位到具体阶段（接收合并/排序/行重建/解析/布局/滚动），
     在接收或呈现模块内部做最小改动，同配置重测并保持行为测试全绿；未命中则记录数据与不改动结论。
   - 验收：无收益的改动回退并记录；不新增第二份消息/活动权威；对外接口不变。

6. **组合与证据收口** — 阻塞于：5
   - 交付：`combo.json` rikkahub `productCommit` 更新、证据索引条目、#45 交接指针；#74 按 issue tracker 方式关闭。
   - 验收：`npm run combo:verify` 通过；证据链接可解析。
