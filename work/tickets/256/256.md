# #256 Android Fairy 互动：统一存在感、反应与台词编排

- GitHub：<https://github.com/eafen405/OurFairy/issues/256>
- 状态：OPEN

## 原标题

Android Fairy 互动：统一存在感、反应与台词编排

## 原正文

## Problem Statement

Fairy 目前在首页与对话页像两套表现：首页固定显示待机，只响应手指、待机计时与唤醒；对话页私下计算存在感，却没有同样的眼部互动。发送消息、收到输出或投递、回到前台等真实事件没有形成一致回应。

理解或增加一次互动，需要同时修改页面计时、存在感合成、眼部控制、台词选择与台词记忆。部分反应能力已经存在但没有真实事件源，测试更多验证布局几何，而不是用户能看到的互动行为。未来新增页面时，这种分散会继续复制，并诱发与具体 UI 或游戏引擎的耦合。

## Solution

在 Android 客户端建立一个不依赖具体渲染引擎的 Fairy 互动 module，统一拥有存在感、屏幕待机、眼部反应和台词选择。页面只负责采集真实事件与渲染结果，不再各自推导互动规则。

首页与对话页使用同一份规则。首页只观察当前会话，即最近选择、缺省回退主会话的会话；不汇总账号下所有会话，也不推断 Fairy 的全局 active、wandering、sleeping 状态。

跨页面时，存在感、屏幕待机与最近台词记录保持连续；正在播放的台词和短暂眼部反应随页面退出结算，不在另一页补播。首批新增互动优先使用眼部和存在感，不为每个事件强插台词。

## User Stories

1. 作为用户，我希望首页的 Fairy 能显示当前会话真实的连接与活动表现，以便我不再看到一个永远待机的外观。
2. 作为用户，我希望首页与对话页的 Fairy 使用同一套存在感语义，以便切换页面时不会觉得她变成了两套人格。
3. 作为用户，我希望拖动或触摸页面时 Fairy 能看向我的操作，以便获得直接而轻量的回应。
4. 作为用户，我希望屏幕待机后点击能唤醒 Fairy，以便继续互动。
5. 作为用户，我希望发送消息后 Fairy 有短暂的注意反应，以便知道我的操作已被客户端接住。
6. 作为用户，我希望收到 Fairy 输出或投递消息时有短促的视线或眨眼反应，以便新内容到达不只表现为列表变化。
7. 作为用户，我希望从后台回到当前页面时 Fairy 能恢复合适的表现，以便界面不像静止截图。
8. 作为用户，我希望同一次活动或投递在重连、切页后不会反复触发反应，以便互动不吵闹。
9. 作为用户，我希望 Fairy 不因为本地动画而伪装成正在思考，以便呈现始终忠于后端事实。
10. 作为用户，我希望后端活动未知时不被显示成安静，以便不会得到错误的安心感。
11. 作为用户，我希望安静会话中已有投递事实可以引起注意反应，但不会被显示成仍在执行，以便区分送达与运行。
12. 作为用户，我希望切换页面后最近说过的台词仍被记住，以便 Fairy 不因页面变化立刻重复自己。
13. 作为用户，我希望离开页面时未播完的台词自然结束，以便不会在另一页突然出现过时的台词。
14. 作为用户，我希望短暂眼部反应不会排队到下一页补播，以便操作反馈始终对应当下上下文。
15. 作为用户，我希望 Reduced Motion 下仍能获得状态与内容反馈，但没有不必要的持续动画，以便保持舒适与可访问性。
16. 作为用户，我希望账号或会话切换后旧事实不会引起新页面的反应，以便互动归属正确。
17. 作为维护者，我希望新增一种互动只修改 Fairy 互动 module 和相应事件采集，以便规则具有 locality。
18. 作为维护者，我希望首页、对话页和未来页面复用同一 interface，以便获得 leverage 而不复制规则。
19. 作为维护者，我希望眼部、台词与计时不再各自拥有互相手工同步的状态，以便消除跨 seam 泄漏。
20. 作为维护者，我希望没有真实事件源的反应分支被接线或删除，以便不继续维护不可达能力。
21. 作为测试者，我希望用事件序列直接验证可观察的互动结果，以便不必通过像素或私有动画计数猜测行为。
22. 作为未来功能的接入者，我希望 Fairy 互动不依赖 Compose 页面内部或 Unity，以便新模块只跨一个窄 seam。

## Implementation Decisions

- 在客户端 Fairy 表现领域内收拢为一个 deep module；其 interface 面向真实事件与可观察表现，implementation 统一拥有存在感合成、屏幕待机、反应调度、台词选择与最近台词记忆。
- 该 module 保持纯 Kotlin 与事件驱动，不引入 Unity、游戏引擎、通用插件注册表或新的渲染帧循环。现有渲染与动画时钟继续复用。
- 首页只读取当前会话的 RemoteActivity 与连接事实。当前会话沿用最近选择、缺省回退主会话的定义；不做账号级活动并集，不创造新的后端状态。
- 存在感仍只包含待机、思考、说话、连接中、离线。活动原因可以驱动注意反应，但不得把投递、任务或报告一概映射为执行中。
- 后端活动未知保持未知语义；安静但带有完成或投递事实时，可以产生短暂反应，不得进入思考或说话。
- 第一批事件包括既有手指跟随与唤醒、发送消息、收到 Fairy 输出或投递、回到前台，以及页面和会话切换所需的生命周期事件。
- 发送消息的本地反馈只表示注意已接收，不提前伪造后端思考状态；后续存在感仍由远程事实驱动。
- 使用现有活动 episode 与投递序号等事实避免同一事件在重连、重组或跨页后重复触发；不为去重建立第二份会话活动权威。
- 持续状态跨页面保留：当前会话衍生的存在感、屏幕待机、最近台词记忆。账号切换或凭据失效时，旧账号衍生状态必须退休。
- 短暂状态随页面退出结算：未播完台词、视线刺激、眨眼或受惊反应不跨页排队，不在返回时补播。
- 台词沿用现有文本与本机最近台词记忆，不进入会话日志、不发送到后端。本票不新增文案，也不要求每个事件都产生台词。
- 台词池按触发语义收拢；没有真实调用方的对话页台词池、紧凑台词分支和眼部反应分支，要么接入本票明确事件，要么删除，不保留假设性能力。
- 页面只采集事件并渲染 module 的可观察结果；不再由页面私下计算存在感，也不再手工同步两份 asleep。
- 所有动画继续服从现有 Reduced Motion 与生命周期约束；不增加持续后台动画，不改变既有视觉令牌。
- 按两个阶段实施并可分别审查：先保持现有行为地收拢规则，再接入首批新事件。两个阶段属于同一交付，不以纯重构代替新互动。

## Testing Decisions

好测试只从 interface 断言外部可观察行为：给定本地事件、远程活动事实与时间推进，断言存在感、反应意图、台词选择与结算结果；不断言私有动画计数、内部类结构或具体绘制像素。

- 主要测试 seam 是新的 Fairy 互动 module interface。用可控时钟、确定性随机与远程事实替身覆盖事件序列，这是唯一新增的行为测试 seam。
- 现有 Compose/Robolectric 页面 seam 只保留高层接线和可见结果测试：首页不再固定待机、对话页与首页一致、手势可达、Reduced Motion 生效、退出页面不补播。
- 不为眼部、台词、计时分别新增彼此独立的测试 seam；它们的规则验证集中到 Fairy 互动 module interface。
- 覆盖当前会话缺省回退主会话、会话切换、账号切换、活动未知、安静但有投递、同一 episode 重放、同一投递重放、重连与前后台切换。
- 覆盖持续状态与短暂状态的区别：跨页保留存在感、待机与最近台词；未播台词和短暂反应在离页时结算。
- 沿用现有 Fairy 页面测试、眼睛运动测试与远程活动事实测试作为先例；删除只保护旧浅 module 内部细节的测试，不降低外部行为要求。
- 验证不改变既有待机台词位置、唤醒、最终消息呈现与阅读位置；涉及动画的验收分别报告替身测试、构建与真机结果。

## Out of Scope

- 后端 dsh、插件、HTTP/SSE 协议、数据库结构与新的后端接口。
- Fairy 全局 active、wandering、sleeping 状态机的客户端推导。
- 账号下所有会话的活动聚合，以及其他用户操作的直接呈现。
- 新的 Fairy 人格、台词文案、长期记忆或通知语义。
- 通用 GameHost、Unity bridge、游戏模块、独立进程或动态插件系统。
- 页面目的地 catalog、会话列表拓扑和会话接收生命周期的改造；分别由后续规格负责。
- 视觉主题重设计或与本票无关的动画参数调整。

## Further Notes

- 本规格来自新的互动需求，不重开旧首页票的交付范围。旧首页票曾明确不增加活动投影；本规格是有意的新决策，只使用当前会话的真实只读事实，不添加装饰性活动状态。
- 架构遵循 ADR-0001：seam 集中复杂性，不为未来游戏预先增加浅 module。
- 客户端词汇中的 Fairy 互动、存在感、待机、当前会话是本次规格的语义权威；Fairy 互动不等于后端活动。
