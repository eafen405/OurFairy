## What to build

让发送消息、收到 Fairy 输出或投递、回到前台等真实事件触发轻量且一致的眼部或当前表现反馈。反应忠于后端事实，同一活动或投递在重连和切页后不会重复打扰用户。

## Acceptance criteria

- [ ] 发送消息后出现短暂注意反应，但本地发送不会提前伪造后端思考状态。
- [ ] 收到 Fairy 输出或投递消息时出现一次可观察反应，安静会话中的投递不会被显示为仍在执行。
- [ ] 回到前台时恢复与当前事实一致的表现，不补播离开期间积压的短暂反应。
- [ ] 使用既有 episode 与投递序号防止同一事件在重连、重组或跨页后重复触发，不建立第二份活动权威。
- [ ] 账号或会话切换后，旧事件不会驱动新上下文的反应。
- [ ] Fairy 互动 module interface 覆盖全部新增事件序列，现有页面 seam 验证真实接线与 Reduced Motion。
- [ ] 相关 Android 测试、lint 与构建通过；替身测试和真机结果分别报告。
