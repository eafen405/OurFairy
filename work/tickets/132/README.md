## Problem Statement

`IdentityStore` 的公开面有 24 个方法，其中 4 个没有任何生产调用方，另 1 个只被同包内部调用却暴露为公开。读这个类时无法区分「谁会调它」与「因为历史原因还在」。

同时 584 行的文件里混着五组 DDL 常量：用户、索引、群组、上传、投递。它们已经在文件内分块，但读者仍要在一个文件里跨 300 行才能确认某张表属于哪个领域。

## Solution

删掉零生产调用的公开方法，把一个仅内部使用的方法转为私有；把五组 DDL 常量移到各自领域命名的模块，store 只负责拼装与生命周期。

不拆连接、不拆迁移阶梯、不拆事务。这三件事都有必须保留的理由，写在下文的实现决定里。

## User Stories

1. 作为维护者，我想让 `IdentityStore` 的每个公开方法都有生产调用方，这样我删除任何方法前不必猜测它是不是死代码。
2. 作为审查者，我想让公开面从 24 个方法降到 19 个，这样一次代码审查能覆盖完整的接口。
3. 作为维护者，我想让每张表的 DDL 出现在以它所属领域命名的文件里，这样「谁拥有这张表」不需要读注释。
4. 作为审查者，我想让 `meta.schema_version` 仍然只有一个主人，这样版本权威不会分裂。
5. 作为审查者，我想让 `createGroup` 与 `changeGroupMember` 的授权读取与写入仍在同一个 `BEGIN IMMEDIATE` 里，这样「指定 owner 与群原子加入」这条保障不退化。
6. 作为审查者，我想让「版本检查早于任何 DDL」这条断言继续成立，这样被拒绝的新版本文件不会被改动。
7. 作为维护者，我想让 `tests/identity-store.test.mjs` 的行为断言原样通过，这样「只是搬移」有可执行的证据。
8. 作为维护者，我想让 `tests/identity-interfaces.test.mjs` 的「store 不离开包」断言继续成立，这样领域面没有泄漏存储细节。
9. 作为升级者，我想让业务库继续遵循「一个插件 = 一个文件 = 一个版本戳」的生态惯例，这样它不依赖一种 dsh 里不存在的存储协作模式。
10. 作为维护者，我想让这次改动不触碰连接、事务原语与迁移顺序，这样风险面可以一句话说清。
11. 作为审查者，我想在被删方法的测试断言同步删除时看到原因，这样删除不是静默的行为损失。
12. 作为维护者，我想让后续「方法按域拆文件」成为一个可选步骤而不是必须先做的决定，这样收窄接口与重组文件可以分开评估。

## Implementation Decisions

- 删除 `userByName`、`listUsers`、`inviteState`、`liveSessionCount` 四个公开方法。前两者只有测试调用，后两者零调用。删除时同步删除对应的测试断言，并在提交说明里写明「测试是唯一调用方」。
- `readDelivery` 转为模块私有（`#readDelivery`），它只被同包的 `prepareDelivery` 与 `prepareDeliveryFile` 调用。
- 五组 DDL 常量拆到 `src/schema/` 下以领域命名的模块，各自导出自己的 DDL 片段；store 导入后拼成唯一一份 `SCHEMA` 字符串并照旧一次性执行。这是纯文件搬移，行为零变化。
- 不拆连接：`BEGIN IMMEDIATE` 是连接级的。多连接会让 `createGroup` / `changeGroupMember` 的跨表事务失效，直接丢掉「授权与写在一起」。
- 不拆迁移阶梯：`#migrate()` 是一次幂等重放加一条形状探测式 `ALTER`，版本戳在同一个事务里最后写入。拆成多个注册者会产生多份版本权威，或在版本检查之前执行 DDL。
- `#transaction` 保持私有。若将来需要领域包在同一事务里协作，正确做法是把它提升为唯一的公开事务入口，而不是暴露裸连接。
- `meta` 表保持由迁移阶梯独占，不并入任何业务域。
- 不采用「每个领域一个包」的方案。评估结论是它搬动复杂度而非移除复杂度，且与生态惯例相反。

## Testing Decisions

好测试只断言外部行为：一次调用产生的结果、一次事务失败后文件的状态。不断言 DDL 写在哪个文件里。

- 接缝：`IdentityStore` 的公开接口本身就是接缝，既有测试已经从这里进入，不新增。
- `tests/identity-store.test.mjs` 的迁移断言必须原样通过，尤其「拒绝更高版本文件且不改动它」与「无外键、无唯一索引、逻辑删除列存在」这两类。
- `tests/identity-interfaces.test.mjs` 的领域面键集断言必须更新到删除后的形状，并在提交说明里写明删除的方法为什么没有消费者。
- 先前艺术：同一个文件里既有的行为断言（并发注册、短编号不复用、删除后不可登录）就是这次改动该照抄的形状。
- 全量门槛：`npm test` 与 `npm run combo:verify`。

## Out of Scope

- 把 DDL 拆到多个包。
- 把 store 拆到多个数据库文件。
- 修改 `meta.schema_version` 的归属。
- 把 `#transaction` 公开化（除非出现真实需求，另开票）。
- 重新设计任何领域面的方法签名。
