## What to build

让每位用户拥有独立印象并直接注入对应会话；Fairy 和用户都能有意识地先读后改，用户可在客户端查看和整份编辑本人印象。

## Acceptance criteria

- [ ] 印象只注入对应用户的模型上下文，其他用户和管理身份均不能读取或修改。
- [ ] 用户印象读写由登录身份确定，不提供他人选择参数。
- [ ] Fairy 的印象编辑是有意识动作，不随记忆维护自动发生，也不因时间流逝自动失效。
- [ ] 用户和 Fairy 均须先成功读取当前印象才能编辑。
- [ ] 客户端提供本人多行纯文本查看与整份编辑，读取成功前不能提交编辑。
- [ ] 印象长度上限和错误反馈生效，超长写入不会被静默截断。
- [ ] 印象与长期记忆、skill 的归属保持区分，不开放长期记忆全库编辑器。
