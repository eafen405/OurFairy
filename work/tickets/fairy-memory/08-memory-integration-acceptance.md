## What to build

把已完成的记忆、印象、维护和自动压缩行为作为一个跨端增量验收，并用 MiniMax 真实模型检查记忆写入质量、失效删除和跨用户分寸。

## Acceptance criteria

- [ ] 所有前置票的功能已集成到同一可复现版本组合，不遗留以集成票名义延后的业务功能。
- [ ] 后端、dsh 和 Android 的相关测试及最终全量门禁通过，版本组合核验通过。
- [ ] 真实模型验收只使用 MiniMax，覆盖明确要求记住、偏好、无意义寒暄、不确定观察、事实更新和失效删除。
- [ ] 真实模型验收覆盖普通与私密切换、跨用户分寸、维护略过及不得重复写入，结果逐条记录。
- [ ] 真实模型质量证据与模型替身、构建和静态检查分别报告，未执行项明确保留。
- [ ] 形成完整交付证据并复核父规格各项行为，不修改或关闭父票。
