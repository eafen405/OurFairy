## What to build

让每个源会话在达到动态门槛且静默时启动轻量模型维护子会话，只处理冻结区间的限定材料，并并行完成记忆新增、更新、删除或略过。

## Acceptance criteria

- [ ] 默认以 15 个闭合用户回合为初始门槛，随最新闭合消息每满 6 小时减 1，最低为 1。
- [ ] 只有达到当前门槛且源会话处于静默会话状态时才启动，搁置区间也会按时重评。
- [ ] 维护只处理上次完成后的新增区间，开始维护即封口，之后的内容进入下一区间。
- [ ] 子会话只含用户消息、Fairy 回复、附件名称和记忆变更调用，只能使用长期记忆工具，不能编辑印象或使用其他工具。
- [ ] 维护子会话不继承其他主会话上下文，不出现在用户会话列表或搜索，来源通过 parentSession 可信解析。
- [ ] 源会话与维护子会话并行，每个源会话同一时间至多一个维护子会话。
- [ ] 零写入也算完成并推进水位，失败不推进，恢复同一子会话，重启后按持久状态重算。
- [ ] 默认维护模型为 MiniMax-M3.1-Flash，主会话模型选择不受影响。
