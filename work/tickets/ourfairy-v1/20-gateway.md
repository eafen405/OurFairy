## What to build

法厄同能在网关管理共用供应商、模型及现有 ASR 连接配置；自定义供应商与模型复用 dsh 的 `llm-pi-ai`。共用选择从各会话下一轮回复生效，正在执行的回复继续用原模型完成。代理人保持对话入口；APK 的可达能力按首版范围收束。

涉及仓库：OurFairy、rikkahub fork。

父规格用户故事：5、6、7。

依据：[前端最终决议](https://github.com/eafen405/OurFairy/issues/10#issuecomment-6165782525)；[实施路线最终决议](https://github.com/eafen405/OurFairy/issues/22#issuecomment-6167313227)。

执行交接：遵循父规格的 implement-spec 集成方式，在匹配的独立 worktree 中完成本票；主集成组合记录实际配套提交。测试沿已确认的真实装配/公开接口，结论附实际检查与未执行条件。仅完成本票不表示整个首版或真机验收已经完成。

## Acceptance criteria

- [ ] 实现上述共用配置的读取、验证、保存及生效/失败反馈；后端核对法厄同资格，复用 dsh profile/settings 与原生凭据机制，对可编辑字段和操作作明确限定。
- [ ] 共用模型使用 MiniMax（`minimax-cn` / `MiniMax-M3.1-Flash-Preview`），复用 `llm-pi-ai` 的供应商、协议、端点、模型清单及能力定义；官方 Flash 路由保留为可切换备选。实际订阅与凭据适用性由集成票核实，密钥在后端维护。
- [ ] 多会话、既有及冷恢复会话都满足父规格的下一轮选模规则；用“模型首请求—工具暂停—法厄同切换—同轮续请求—下一轮”观察两个模型替身的实际请求，覆盖在途回复和排队输入。
- [ ] 会影响在途回复所用路由的端点、协议或模型定义修改、删除或重载返回在用状态；按实际影响范围覆盖与新回复开始的并发及失败恢复。保存共用选择不受此限制，按下一轮生效。附件能力检查与实际执行选择一致。
- [ ] 保存后重启仍保留运行时选择及自定义配置；启动装配不以组合中的初始默认覆盖运行时设置。缺失配置编辑能力、无效输入或凭据写入失败均明确报告。
- [ ] 邀请入口继续使用已有真实邀请流程，普通代理人直调管理请求被拒绝；管理者仍无他人正文、私有文件或未加入群组的读取权。
- [ ] 按首版功能表收束导航、注册和可达能力，排除 TTS、媒体生成、个人模型、Web server、备份、QR 分享等；群组经对话、任务经活动卡，无额外管理中心。
- [ ] 插件安装、启停和装配由部署维护；法厄同手机入口只提供已定的产品配置操作。
- [ ] 已交付对话、显示偏好、附件/ASR/PDF 等入口的配置契约保留，尚未并入的功能不擅自恢复原本地执行；后续并入后按同一能力声明启用。
- [ ] 用真实身份与配置持久化验证法厄同/代理人可见和可调用范围、无效配置及重启恢复；产出可构建的一 APK，而不依赖隐藏 UI 当作授权。
