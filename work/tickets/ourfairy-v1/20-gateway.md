## What to build

法厄同能在网关查看/调整首版共用后端配置，代理人保持对话入口；APK 中未纳入首版的旧功能不可绕过产品职责被调用。

涉及仓库：OurFairy、rikkahub fork。

父规格用户故事：5、6、7。

依据：[前端最终决议](https://github.com/eafen405/OurFairy/issues/10#issuecomment-6165782525)；[实施路线最终决议](https://github.com/eafen405/OurFairy/issues/22#issuecomment-6167313227)。

执行交接：遵循父规格的 implement-spec 集成方式，在匹配的独立 worktree 中完成本票；主集成组合记录实际配套提交。测试沿已确认的真实装配/公开接口，结论附实际检查与未执行条件。仅完成本票不表示整个首版或真机验收已经完成。

## Acceptance criteria

- [ ] 实现首版已定共用系统配置的读取、验证、保存及生效/失败反馈，后端决定管理资格；不是客户端直接编辑业务数据库。
- [ ] 共同模型配置保持已定官方 Flash 和后端凭据职责，变更能力时显式校验输入兼容；不引入个人模型/凭据入口。
- [ ] 邀请入口继续使用已有真实邀请流程，普通代理人直调管理请求被拒绝；管理者仍无他人正文、私有文件或未加入群组的读取权。
- [ ] 按首版功能表收束导航、注册和可达能力，排除 TTS、媒体生成、个人模型、Web server、备份、QR 分享等；群组经对话、任务经活动卡，无额外管理中心。
- [ ] 已交付对话、显示偏好、附件/ASR/PDF 等入口的配置契约保留，尚未并入的功能不擅自恢复原本地执行；后续并入后按同一能力声明启用。
- [ ] 用真实身份与配置持久化验证法厄同/代理人可见和可调用范围、无效配置及重启恢复；产出可构建的一 APK，而不依赖隐藏 UI 当作授权。
