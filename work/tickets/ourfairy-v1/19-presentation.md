## What to build

客户端保留 Fairy 视觉与本地显示偏好，长回复及时可读、流式时可滚动，结束/停止/错误后完整呈现格式并保持阅读位置。

涉及仓库：rikkahub fork、必要的 OurFairy 客户端事件适配。

父规格用户故事：70、71、72、73、74、75。

依据：[前端最终决议](https://github.com/eafen405/OurFairy/issues/10#issuecomment-6165782525)；[共同接口研究](https://github.com/eafen405/OurFairy/issues/20)。

执行交接：遵循父规格的 implement-spec 集成方式，在匹配的独立 worktree 中完成本票；主集成组合记录实际配套提交。测试沿已确认的真实装配/公开接口，结论附实际检查与未执行条件。仅完成本票不表示整个首版或真机验收已经完成。

## Acceptance criteria

- [ ] 复用 Fairy 眼睛动效/回复面板和视觉资源，接既有会话投影；本票消费状态，不实现另一套活动聚合。
- [ ] 深浅色和字体偏好保存在设备本地；消息列表/详情使用同一呈现入口，用户主动滚动时不强行追随。
- [ ] 原始内容无损累积，显示调度只合并过时的完整快照；长回复不会持续消费已经过时的队列。
- [ ] 流式可显示保留格式符号的纯文本，终态从完整原文生成预期 Markdown/代码/表格/公式，覆盖跨段引用和只改结束状态的情况。
- [ ] 停止、错误、历史恢复与重连批量内容都正确收尾；旧任务不能覆盖终态，最后增量不漏，切换格式不闪空白、重放内容或破坏阅读位置。
- [ ] 固定长历史、长单条、代码/表格/公式、持续流式滚动和重连突发的可重复工作负载，记录当前基线及据此制定的性能门槛。
- [ ] 完成相关呈现/滚动状态测试和 release 构建可运行测量入口；不以旧 16 ms 常量或冷启动基准当作长回复已达标，目标设备结果由真机票验证。
