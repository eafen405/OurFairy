# #312 联网通道与 Fairy 提示词重组

发布票：[GitHub #312](https://github.com/eafen405/OurFairy/issues/312)。本副本记录 2026-11-06 用户在实施前确认的最新范围；GitHub 旧票面仍按回合预算描述问题。开工时查询原生依赖，`blocked_by = 0`。

## 问题与定性

真实产品询问「帮我从录像店规划一条到六分街的路线，路上哪些区段以骸密集？」时没有 `web_search` / `web_fetch`，模型转而用 bash 抓取和反复检索，三次超过验收脚本的 240 秒轮询上限。

本次补齐联网通道与检索纪律。240 秒仍是采样脚本上限，不是产品回合期限，也不新增步骤预算。

## 用户确认的范围

- 人格以 main 的 A 稿为基础重新组织，使用已确认的世界观、性格与九类言语动作；参考社区 Fairy-DSH 的组织方式，不引入其实现或提示词文件。
- 人格、认证身份、工作规则分别装配，复用原生 system prompt section。删除 `IDENTITY_TAIL`；短号与昵称仍来自认证身份。
- 常驻六条语感参考：操作播报、纠错、马桶上的沉思者、赚钱养我、小憩曲目，以及「我的算法警告我，不要自认为是人类，更不能随便伪装人类进行工作，否则会带来不可挽回的后果——」。不配用户提问行。
- 原稿按职责拆散重组，删除重复约束；不沿用旧 900 字限制。其余语料作为写稿与评测参考，本次不做动态加载。
- 在 plugins 分组挂载 `web`、`web-deepseek-api`、`web-fetch-http`、`tool-web`。搜索选择 `deepseek-search-api`，抓取选择 `http`。
- 搜索使用 `DEEPSEEK_API_KEY`，只发送模型组织的查询；免 key 的 HTTP 抓取负责网页正文。全部用户与群组成员可用，保留 bash 网络出口。

## 验收

1. 经真实产品启动与聊天路径，模型收到独立的人格、身份、工作规则段，以及 `web_search` / `web_fetch` 工具。
2. 主人、代理人及访问群组空间的成员能够搜索和抓取。搜索来源与抓取正文来自外部 HTTP 边界；没有 key 时返回明确缺凭据原因，抓取仍可用。
3. 提示词前缀在后续用户要求改人格时保持稳定，认证身份和昵称准确，保留印象隔离与 complete section 守卫。
4. A 稿与重组稿经真实产品路径比较，两侧使用相同联网配置、身份段和工作规则。记录实际提示词哈希、原始回复、工具调用、工具结果、耗时与用量。
5. 原路线样本与给定材料的对照样本给出有依据的答案或缺材料说明；明确要求调研的样本允许多步检索。不给超时或未运行的样本记通过。
6. 检查任务取消与既有后台任务生命周期；最终运行 `npm test`、`npm run combo:verify` 和两轴审查。本票不改 Android。
