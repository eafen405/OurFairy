## What to build

让用户把现成技能地址交给 Fairy 即可形成候选，并可以显式提议为共有技能，由法厄同审核后供各位用户自行启用。补齐共有提案通知、审核结果通知、技能归档与恢复，使用户能够维护技能的完整共享生命周期。

## Acceptance criteria

- [ ] Fairy 可以从远程技能包或仓库地址获取内容，记录来源、固定版本、规范化清单哈希和许可证；分支后续变化不会改变已取得的候选。
- [ ] 地址获取与解包拒绝路径逃逸和符号链接，外部内容只进入隔离候选区，不进入原生扫描根或注册宿主代码。
- [ ] 外部候选复用 #297 的验证、审核和发布路径，未经批准不会影响任何会话。
- [ ] 普通用户可以在当次用户回合显式提议共有；后端记录提议者、来源用户和共享同意，模型不能自行选择所有者或批准人。
- [ ] 同一作用域、所有者与名称至多一个有效技能身份；同范围撞名转为修订候选或明确拒绝，个人与共有之间允许按规则遮蔽。
- [ ] 共有候选只对提议者与法厄同可见，审核材料仅含清理后的候选包、来源摘要和验证报告，不开放提议者的其他个人技能或原始会话。
- [ ] 法厄同可以批准或拒绝共有候选，普通提议者不能使其全局生效；批准与拒绝结果提醒提议者一次，新共有候选提醒法厄同一次。
- [ ] 共有技能批准后，无偏好记录的用户默认禁用，每位用户可以独立启用；审核人不会替其他用户选择。
- [ ] 个人技能仅所有者可归档和恢复，共有技能仅法厄同可归档和恢复；后台创建器没有这些权限。
- [ ] 归档退出选择池并保留内容、来源、审核历史和启用偏好，恢复不重置偏好，无偏好时沿用个人启用、共有禁用默认值。
- [ ] 客户端展示归档、待审修订和动作作用域，归档、恢复、共有发布与启停会刷新所有受影响在线 Agent。
- [ ] 真实后端、网络替身、通知与 Android 测试覆盖安装、共有提案、隐私、权限和生命周期。
