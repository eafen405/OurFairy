## What to build

让系统在轻量粗判后，只对同一用户、同一类工作流在两个独立会话中的有效成功证据进行一次深度创建，形成新技能或技能修订候选并提醒用户审核。检测与创建保持增量、可恢复、可去重，晚到纠正能够撤销证据，普通对话不会被迫产生技能。

## Acceptance criteria

- [ ] 每个源会话按增量水位、冻结切点、静默准入和源会话并行执行检测，后续交互进入下一区间。
- [ ] 检测材料包含所需用户消息、Fairy 回复、附件名称、工具调用与结果和文件变更摘要，不复制完整环境快照。
- [ ] 检测子会话从源会话派生所有者，使用轻量模型与有界材料/轮数预算，清空继承工具，只通过自注册结构化工具提交信号。
- [ ] 零信号完成也推进水位；检测失败不推进并恢复同一子会话，完成以持久回合结束和结构化提交为准。
- [ ] 检测提示携带该用户现有任务键的有界清单，任务键由任务类型与产物组成并优先复用，不跨用户累计。
- [ ] 只有两个不同源会话的有效成功信号才达到深挖门槛；单次、失败、撤销和无法确定的经历不触发。
- [ ] 用户纠正、投诉或否认会否决证据，包括纠正晚于冻结切点的情况；创建前重新检查贡献信号及其后续纠正。
- [ ] 同一所有者与任务键的创建认领原子唯一，两个并发检测只能产生一个深度创建任务。
- [ ] 创建认领独立保存贡献信号、子会话、重试和候选；创建失败不回滚检测水位，也不阻塞源会话后续学习。
- [ ] 创建子会话只拥有有界证据读取、候选提交、验证执行与无操作工具，复用同一 Skill Creator 内容，真实执行记录由系统保存。
- [ ] 深度创建复用 #297 的候选路径和 #299 的进化路径，可以形成新技能候选、技能修订候选或明确无改进，并对已有候选和处理过的信号去重。
- [ ] 后台候选通过既有通知面和技能页待审徽标到达用户，Fairy 不在普通对话中主动插话。
- [ ] 真实模型小规模验收覆盖无意义对话、重复成功、晚到纠正和去重，记录轻量/深度调用次数与 token 成本，不以大规模重复验证作为质量门槛。
- [ ] 真实后端测试覆盖并发认领、跨用户隔离、重启恢复、通知和端到端自动候选。
