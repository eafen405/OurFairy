## What to build

让用户通过一句“把刚才的流程做成 Skill”创建完整技能候选，并在本人主会话中与 Fairy 完成查看、批准、要求修改或拒绝。所有技能包共用同一条创建、必要验证、审核和发布路径，首次批准的个人技能默认对本人启用。

## Acceptance criteria

- [ ] Fairy 可以按需激活内置 Skill Creator，并按用户指定的本轮任务或 turn 范围读取实际工作流材料。
- [ ] `skill_manage create` 接受明确的材料范围、个人意图和模型起草包，后端派生所有者并把内容校验后写入隔离候选区；模型不能选择落盘位置或所有者。
- [ ] 每个候选都在同一验证流程中按代表场景完成必要执行与环境准备，报告来自真实命令、退出码和执行环境，而不是模型自述。
- [ ] 验证环境不修改共享环境根；环境准备实际命令、来源与版本随候选验证报告保存。
- [ ] 候选不会进入模型可见技能 provider，也不会在审核前影响当前版本。
- [ ] `skill_manage list` 与 `inspect` 能返回真实待审候选、完整只读审核包和允许的下一动作，不需要模型猜测编号或材料。
- [ ] 客户端待审入口固定进入本人主会话，候选引用以系统上下文注入，不伪装成用户输入。
- [ ] 审核展示行确定性呈现差异、适用边界、目标收益、包内容变化、执行记录和按需展开全文方式，不要求把全文塞进一条消息。
- [ ] 个人所有者可以批准、要求修改或拒绝；要求修改形成重新验证的新草稿，旧批准与旧验证不能沿用到新哈希。
- [ ] 审核与发布原子校验候选状态、包清单哈希、归档和当前版本，重复批准或内容变化不能发布。
- [ ] 个人技能首次批准默认启用，发布后通过 #296 的原生目录与激活路径立即可用。
- [ ] 使用期环境准备遵守当前会话权限并留在当次会话记录中，失败说明缺失内容、已尝试动作和本次不可用状态，不改写已审核报告。
- [ ] 工具描述、Skill Creator 与记忆维护提示明确可复用工作流进 Skill、稳定事实与偏好进记忆，不双写。
- [ ] 真实后端与 Android 测试覆盖创建、验证、审核、发布、越权和恢复路径。
