## Question

首版已保留语音输入和附件选择/上传/下载，同时对话模型仅接官方 DeepSeek、VOICE_API_KEY 用于硅基流动 ASR。这些已选能力从 Android 输入到后端存储、模型或工具实际消费是否能够闭合？缺失的最小适配是什么，是否存在必须回报用户的能力冲突？

类型：AFK research。研究事实与适配建议；不得将“可上传附件”自动扩大为模型原生理解任意图片、音视频或文档。

- 从 rikkahub 与旧 Fairybot 追踪录音、转写、编辑/发送和错误处理链路；核实硅基流动官方 ASR API 的认证、可用模型、输入格式与请求方式。只读源码和官方文档，不读取或打印真实密钥，不发起付费请求。
- 区分 ASR 转写与共用 DeepSeek 对话模型；给出凭据放置及端到端请求职责的最小建议，不默认把共享密钥放进 APK。
- 从选择/上传到不可变附件引用、会话资格、模型投影、工具读取、投递及下载，追踪文本文件、图片、一般二进制文件的实际路径；说明“能保存/交付”“工具可读取”“模型直接理解”的差别。
- 核实所选 dsh provider 与 DeepSeek 官方当前文档的输入能力；历史研究或模型名称不能替代当前证据。对服务文档日期/模型版本变化明确限定，不自行引入新 provider、OCR 服务或新产品功能。
- 输出兼容性表、推荐接口职责和失败/不支持场景；仅当既有承诺确实无法满足时，提出具体影响和可供后续决策的选项。
- 本轮用户新增约束：不做音视频附件理解兼容，ASR 语音输入仍沿用；已确认 PDF 支持文字提取及扫描页/图表按需读图。见[用户范围澄清](https://github.com/eafen405/OurFairy/issues/22#issuecomment-6166922935)。核查已有 PDF 提取/渲染能力及后端最小增量；明确官方视觉模型依赖、页码定位及失败边界。支持范围已定，库/参数及具体接线仍由本票提供建议。

依据：[前端最终决议](https://github.com/eafen405/OurFairy/issues/10#issuecomment-6165782525)、[后端最终决议](https://github.com/eafen405/OurFairy/issues/9#issuecomment-6163738839)、docs/research/message-model.md 及三项目固定版本源码。官方接口文档须附可复查 URL 和访问日期。

完成标准：单份一手来源研究报告，能指出首版输入链路哪些已有可复用实现、哪些需补接线、哪些需要后续人工选择；不实施 ASR 或附件服务。
