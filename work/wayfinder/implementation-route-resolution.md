## Resolution：首版实施路线、共同接口与活动合并

用户已完成本票现场讨论：先以“23按推荐”确认首次通知基线和实施路线，在了解原生字段后进一步确认“合并计算是合理的”。结合此前已确认的 PDF 范围，本图所需决定已收束。完成的是工程实施前的路线，未实施产品、完成构建或通过真机验收。

### 实施路线与改动位置

采用先稳定会话与持久化、再接共同接口的路线，各模块维护自身规则，装配仅连接依赖。

| 顺序 | 产出及进入后续集成的门槛 |
| --- | --- |
| 1. 固定来源与显式装配 | 建立可保存自身改动的 dsh/rikkahub fork 与固定提交，OurFairy 建产品构建骨架、独立依赖锁定和显式 profile；隔离数据目录、明确查询配置；无真实凭据/模型请求的完整启动检查须确认服务、工具、投影就绪及排除能力未挂载 |
| 2. 原生会话事实 | 永久归属、正式投递及必要任务事实贯穿 Session、消息、格式/catalog、surface、恢复与查询；完成两用户创建/持久化/恢复/越权拒绝和格式往返 |
| 3. 最小投递与恢复链路 | 认证后发送/读取、向固定主会话投递、按持久截点补齐；覆盖 live/cold/生成中追加、同 deliveryId 去重、落盘后故障恢复，收件方不启动推理 |
| 4. 并行能力适配 | 以已定归属、消息及写入接口接同用户检索、空间/fs/sandbox、jobs、附件、ASR、PDF 和 Android 远程同步；每个模块以接口行为验证，集成遵循前述依赖 |
| 5. 产品集成 | 一 APK 按身份入口、统一活动与通知、活动卡/任务详情、分别停止回复和任务、文件/PDF/语音输入、最终格式和阅读连续性 |
| 6. vivo S50 验收 | release 构建测后台/锁屏/断线/回收恢复、长回复/滚动、接收到呈现延迟及内存；模型首个内容等待单独计量，修复不符合既定行为的结果 |

这不是开发工期承诺。阶段 2/3 的多数行为可通过无网络模型替身、序列化检查和持久化故障测试验证；真实 provider/ASR 与真机在对应集成阶段验收。

dsh fork 承载连贯的原生公共表示与消费端修改；OurFairy 承载产品模块、受限文件/执行适配及启动配置；rikkahub fork 承载远程接线、客户端同步、展示和通知。复用旧 Fairybot 的局部实现，按新的身份与生命周期适配，不整体继承原宿主结构。

当前本地 dsh/rikkahub checkout 的 origin 仍指向上游；实施须固定实际包含产品改动的提交，不能把当前上游 SHA 当作修改后的交付。dsh 遵守其 profile/ordered patches 启动要求，不另造 SDK 内联应用树。依各项目锁定构建工具与产物，Android 按 rikkahub 自身 SDK 37 验证，不套用旧 Fairybot SDK 36。目录/workspace、版本字段、表定义、解析库和具体协议编码由实现落实，不逐项重新请求产品选择。

### 共同接口及持久事实

- 身份模块提供可信请求者；会话模块维护永久归属、主会话、日志、写入生命周期、授权后的检索/控制及内部窄投递追加。法厄同管理身份不授予他人个人内容读取权。
- 会话 header 保持归属权威，业务 SQLite 保存已定业务关系/协调记录，查询索引可重建，附件内容不可变。无归属旧日志不得默认为用户 1；格式变化通过明确后继格式/兼容路径处理。
- live 追加复用同一 Session/writer，cold 追加取得同一生命周期协调下的独占 writer；不为投递创建推理。deliveryId 先固定，按日志核对协调 JSONL/业务库重试，通知失败不撤销正文。
- 正式投递保留真实来源、附件资格和普通 Fairy 消息外观，进入后续模型历史。不得伪造模型 turn/step/stream；DeepSeek assistant 不接受原样 image/file，采用合法、保留真实来源的附件文字句柄及获准图片/PDF 工具读取。
- 客户端会话同步模块提供观察、发送、补历史和分别停止回复/任务的接口，内部处理归并、身份、活动和恢复；页面及通知不直接各自推断原生事件。
- 区分“已观察”与“已保存且完整应用”的前缀。原生 session/event 可早于落盘；捕获截点后等待实际 JSONL writer 的 flush 成功才能持久确认。流式正文可及时显示，恢复游标不可越过未确认或未补齐的事实。
- 复用 dsh HTTP unary/WS stream、follow baseline 与向后 page，固定截点补齐、重叠去重、独立处理并发尾部；throughSeq 不是 afterSeq。原始增量不丢失，只有累计后的完整展示快照可合并。
- 复用 jobs 的运行/输出/停止机制，补齐原会话恢复所需的最小任务生命周期事实；不另建活动权威日志，不承诺输出永久完整或服务器重启自动续跑。

### 激活按会话合并计算

用户已确认后台任务计入激活。每个会话统一合并以下事实：

1. Fairy 正在执行：原生 `Agent.status === 'running'`，对外会话摘要/事件为 `running`。
2. 该会话仍有后台任务：按 `JobView.owner` 限定会话，`JobView.status` 为 `running` 或 `stopping`。
3. 实际待处理的任务结果报告，以及已经保存的投递内容输出。

因此 Agent 已 idle、同会话 job 仍 running 时，会话仍激活。所有实际工作与输出结束才静默；长任务运行期间，中间回复完成不会另发一次结束提醒。其他会话独立计算。

统一活动状态由一个模块推导，`activity.phase` 只是接口命名示意，尚未实现；它不是 dsh 现成字段。不能只凭 `activeAttempt`、是否出字或单个 turn/end 判断全会话结束，也不通过伪造 Agent.running 表示投递。投递仍不启动收件方推理。

任务 settled 与结果报告 followup/inject 是不同事件和生命周期；实现须在任务完成、实际报告排队/运行及结算之间协调，避免短暂 idle 造成活动结束后立即重开和重复提醒。没有安排报告、报告取消/失败时须明确结算，不为不存在的报告永久保持激活。连接中断或未知状态不等于静默；恢复后核对实际事实。

通知继续遵守已定规则：应用前台不弹；静默会话在后台收到投递并输出时提醒一次，随后静默不重复；后台工作最终结束且同次活动未提醒时提醒一次。活跃中收到投递并入当前活动，调用方不另建按来源分叉的提醒规则。断线先补齐内容与状态，再按会话合并尚未提醒的积压。

### 首次同步与通知记录缺失

用户已确认：首次设备或通知消费记录无法恢复时，先同步当前内容和状态，以同步截点建立新基线，历史可正常阅读，但不补发之前全部历史的系统通知。

有有效旧记录的普通断线仍补齐并按会话合并积压；能够恢复旧消费记录时应先恢复，不得把普通断线当作新设备跳过积压。通知消费位置和用户已读位置分开。系统通知与本地记录不具备天然原子事务，不宣称严格恰好一次；崩溃窗口须在集成中验证。

### 共用模型、ASR 与 PDF

首版显式配置 `deepseek-official/deepseek-flash`，满足已确认的图片及扫描 PDF 阅读。复用 dsh 官方 provider，手机不持云密钥。官方 API 名称所指模型版本可能更新，验收记录实际版本/能力，不宣称锁住了服务端模型快照。

ASR 复用旧录音→后端代理→可编辑草稿路径，后端读取 `VOICE_API_KEY`，与 DeepSeek 凭据分离。ASR model 使用部署配置并核对当前官方支持与账号/容器可用性，不硬编码旧文档未承诺的型号；ASR 不自动发消息，不增加全部音频附件兼容。

PDF 按用户已确认范围：后端保留原件，提供页数/目录或少量样本、按页提取文字、扫描页/图表按需渲染图片，再接现有 read_image/官方视觉通路。保留页码和原件下载，不一次把全文塞入上下文，不声称未读页面已理解。解析/渲染模块内部管理资格、资源预算、派生产物及失败；具体库通过平台、构建与样本验证选定。

附件在上传、发送、工具实际读取、投递及下载入口核对资格；内容 hash 相同不授予读取权，投递建立收件方引用资格。图像/PDF 的工具结果到官方模型路径必须实际联调。

音视频内容理解、TTS、媒体生成及此前排除能力继续不纳入首版；ASR 语音输入保留。

### 验证与交接

三份研究和本轮字段核查已给出足够路线依据；完整 Loader 启动、产品编译及真实兼容尚未验证。实施门槛至少覆盖：

- 双用户的创建、恢复、检索、控制、文件、任务和附件范围；群主管理资格在实际变更时检查。
- live/cold/生成中投递、重复 deliveryId、附件失败、flush 失败、跨日志/业务库崩溃及落盘后通知失败。
- 回复/任务/结果报告的活动衔接、多会话独立、投递不推理、双停止、任务输出缺口和重启后未知态。
- 历史截点与并发尾部、baseline、首次通知基线、普通断线积压、前台抑制、账号切换及通知点击。
- ASR 回填/取消/错误与迟到回调，PDF 文字/扫描/混合页/图表/页码/超限及损坏，真实官方图片工具结果。
- vivo S50 release 的后台/锁屏/断网/回收，以及长历史、超长回复、流式滚动、终态完整格式与阅读位置。

已运行的既有探针只有离线注入扫描和当前 Node SQLite FTS5 检查；Loader 因依赖未安装未启动。未做产品功能、付费模型/ASR 调用、Android 构建或真机测量。当前没有需继续成票的独立设计 fog；实施中若出现必须改变产品承诺的具体冲突，再针对实际问题决策。
