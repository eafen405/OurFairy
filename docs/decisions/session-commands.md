状态：交互设计已确认，正式规格已发布为 [#342](https://github.com/eafen405/OurFairy/issues/342)，待实现。确认日期：2026-11-10。

本文记录用户已确认的需求、固定版本的代码事实与实施边界；需求确认不表示功能已经实现。正式规格已转写为[会话命令规格](../specs/session-commands.md)，本记录保留访谈来源与代码调查依据。产品术语见[产品词汇表](../../GLOSSARY.md)，记忆与技能分别遵循[记忆词汇表](../glossary/memory.md)和[技能词汇表](../glossary/skill.md)。

## 用户已确认

1. 首批引入 `/compact`、`/clear` 两个命令。
2. 命令作用于当前打开的本人会话，主会话与普通会话都支持，不改变固定主会话身份。
3. `/compact` 表示上下文压缩，复用原生能力，保留对话连续性。
4. `/clear` 表示上下文重置：重置前的对话原文及会话摘要退出后续模型上下文；它不表示删除会话或删除记忆。旧消息仍保留在当前聊天中，并插入“上下文已重置”分界提示；分界前的消息仍可翻阅，但不再自动带入后续推理。
5. 印象、长期记忆、已审核技能、启用偏好及技能包仍保留并可继续使用。原先激活进对话的技能全文随旧上下文退出，随后可以重新加载；可用技能与当前已激活正文是不同概念。
6. 重置不取消原始日志所支撑的记忆维护与技能学习：旧材料仍可能按现行规则被整理，因此重置不表示让 Fairy 遗忘旧事。
7. Android 输入 `/` 时自动显示 `/compact`、`/clear` 两个快捷选项按钮；输入 `/cl` 时显示匹配的 `/clear` 选项。候选放在输入框上方；点击只补全命令、保留输入焦点，不立即执行，由用户点击发送发起操作。
8. 当前会话正在回复、有排队消息或有尚未结束的后台任务时，拒绝此次上下文操作并提示等待完成或停止后重试；不自动停止这些工作，也不将命令排队等待执行。记忆维护与技能学习保持原有行为。
9. 首批只支持单独输入的完整命令，允许首尾空白，不支持附加参数或混带附件。完整命令带附件时提示先移除附件，不将附件随命令提交；普通正文中提及命令仍作为普通消息。
10. 只有完整匹配命令时，输入框中的命令文字使用现有主题的仪器青色；输入 `/cl` 时只显示候选，文字仍为原色，点选补全为 `/clear` 后才变色。直接手动输入完整命令同样变色，普通文本保持原有外观。
11. 未补全的 `/cl`、未知斜杠文本和带额外说明的文本不触发操作，发送时仍作为普通消息处理；完整命令夹带附件仍按先移除附件的规则处理。
12. 点击发送后直接执行，不增加二次确认。使用系统状态提示展示“正在压缩”“已压缩”“当前无需压缩”“上下文已重置”或具体失败原因；不为命令额外启动一轮 Fairy 回复，失败保留可重试的命令草稿。

确认来源：本次设计访谈中，用户先回复“可以的”接受首轮 Q1–Q3 及事实补充，并提出 `/` 与 `/cl` 的快捷选项交互；随后对 Q4–Q7 回复“按推荐”，并提出命令识别后的变色反馈；最后对 Q8–Q9 回复“是”，确认完整匹配的着色、普通文本行为及系统执行反馈。

## 已核实的代码事实

以下来自只读源码调查，未执行真实会话重置或设备验收。

- 以[组合登记](../../combo.json)锁定的外部 DSH fork `ae2adffd8d67773e125b8048120cf9ad2ba7edf3` 为能力依据；当前 Harness GUI 的安装版本不是产品集成依据。
- [会话服务](../../backend/sessions/src/service.ts)按用户编号确定固定主会话身份，禁止归档主会话；切换当前会话不会替换主会话。现有新建入口可能复用空会话。
- [产品装配](../../backend/v1-bundle/cordis.patch.yml)已经挂载原生自动压缩能力；[聊天入口](../../backend/chat/src/index.ts)没有手动压缩或重置入口。现有发送把这些命令当作普通用户文本。
- 锁定 DSH 的公开 `ctx.compaction.compactNow(agent, signal, sourceCommandId?)` 可以直接调用；原生命令插件本身也调用这一接缝。它使用原生 maintenance 互斥与持久化处理，不必为产品手动压缩引入 Typert 或另一套压缩算法。
- 锁定 DSH 尚未发现可直接调用的上层 clear/reset API。会话 surface replacement 能保留原始日志并改变模型可见内容，但会插入替换节点且有系统消息边界约束，不能将其直接当成现成的“清空上下文”操作。重置的具体日志表达与生命周期接缝仍需设计。
- [记忆维护](../../backend/memory/src/maintenance.ts)和[记忆材料](../../backend/memory/src/material.ts)按原始日志及持久水位处理闭合用户回合；[技能学习](../../backend/skill-creator/src/learning.ts)使用同类原始日志区间。保留日志、会话身份、序号和水位时，上下文重置本身不意味着跳过尚未处理的材料。
- 原生技能全文由工具结果进入模型上下文；当前 surface 不再包含目录时，原生技能预步骤可以重新生成可用目录。目录重建不等于恢复先前加载的全文。
- [聊天投影](../../backend/chat/src/units.ts)依据原始日志构造可见历史，原生压缩替换内容不作为普通消息。仅改变模型 surface 不会自动清掉界面历史；已确认的重置分界需要补充相应呈现。
- [聊天 runtime](../../backend/chat/src/runtime.ts)有同会话顺序执行接缝；现有停止回复请求保留排队输入，且不表示已经等待空闲，后台任务另有停止入口。因此不能把“调用停止接口”解释为“已停止全部工作”。
- Android 当前唯一的聊天输入入口是[会话页](../../android/app/src/main/java/me/rerere/rikkahub/ui/fairy/FairyConversationPage.kt)装配的[聊天面板](../../android/app/src/main/java/me/rerere/rikkahub/ui/identity/RemoteChatPanel.kt)。控制台没有输入框；现有输入区已有草稿、按钮与附件菜单基元，没有斜杠命令候选行为。

## 输入识别与反馈示例

| 输入或动作 | 呈现与处理 |
| --- | --- |
| `/` | 原色；显示 `/compact`、`/clear` 两个候选 |
| `/cl` | 原色；显示 `/clear` 候选；尚未触发命令 |
| 点击 `/clear` 候选 | 仅补全输入并变青色，保留焦点；等待用户发送 |
| 手动输入 `/compact` 或 `/clear` | 完整命令文字变青色；点击发送执行 |
| `  /clear  ` | 首尾空白不影响识别 |
| `解释一下 /clear` | 原色；普通消息，无命令候选 |
| `/clear 帮我重新开始` 或未知斜杠文本 | 未完整匹配命令；原色，按普通消息发送 |
| 完整命令同时带附件 | 提示先移除附件，保留草稿与附件，不将其作为命令附件提交 |
| 会话仍有回复、排队消息或未结束任务 | 明确拒绝此次操作；不停止工作，不排队执行命令 |
| 压缩完成或无须压缩 | 系统状态分别显示“已压缩”或“当前无需压缩” |
| 重置成功 | 留下“上下文已重置”分界；旧消息仍可翻阅 |
| 操作失败 | 展示具体失败原因，并保留可重试的命令草稿 |

## 实施边界与数据影响

以下为承接已确认交互的实施约束；具体公开接口与日志字段在实施中确定。

- 在现有产品插件及 HTTP/SSE 接缝中增加命令受理与结果呈现，复用身份鉴权、会话归属、同会话顺序执行和持久化；不为这两个命令另建通用命令平台、Typert 传输或第二套会话系统。
- `/compact` 直接适配原生 `ctx.compaction.compactNow(...)`，沿用摘要、近期原文保留、maintenance 互斥和失败处理；不新增压缩算法，也不改变部署级自动压缩设置。
- `/clear` 保持原会话身份与原始追加日志，使用原生会话 surface 与维护接缝落实重置。系统提示、人格、身份、工具与印象继续由现有装配提供；重置前的对话、摘要、工具结果及激活技能全文不再自动进入后续模型请求。不能只清 Android 内存或界面来实现重置。
- 数据表达需要扩展现有会话日志中的命令结果与重置边界，并让后端聊天投影及 Android 识别相应系统呈现。旧事件不重写，序号继续追加；不新增业务数据库表，不修改记忆库、技能库或技能包的结构。有限命令类型与结果状态在产品接口中使用数字编码，文案在呈现层映射。
- 命令路径不直接修改印象、长期记忆、技能内容、审核、启用偏好，以及记忆维护与技能学习水位。原有后台处理仍可继续按日志与冻结区间工作；这一点不等于后台库值从此不再变化。
- 忙态在后端执行前检查，并与同会话操作、原生维护互斥协调，不能仅相信客户端状态或原生 `idle` 标签；维护期间也可能对外显示 `idle`。新消息、投递与命令须遵循现有会话顺序，避免重置后混入未协调的旧输入。
- 受理与完成是不同事实。成功反馈以操作结果耐久保存为准；重试沿用原操作身份，结果不明时先恢复原操作结果，避免重连后另发一次重置。必要的恢复状态沿现有接缝落实，不另建平行历史。
- 实施时保留普通消息原有草稿、附件、待确认发送和接收机制；补全与着色复用同一份命令识别规则。失败后的草稿恢复不得覆盖用户随后输入的新内容。

## 验收要求

以下是实施后的行为验收目标，当前尚未执行这些新功能验证。采用真实产品入口与确定性模型替身，直接观察模型请求、原始日志和客户端公共状态；原生能力的内部细节不由产品另抄一套算法断言。

| 场景 | 需要核验的行为 |
| --- | --- |
| 输入 `/`、`/cl` 与点击候选 | 候选正确过滤；点选只补全且保留焦点，没有网络受理或模型调用 |
| 手输完整命令、补全及删除字符 | 只有完整匹配时使用青色；删回前缀后恢复原色；补全与着色读取同一规则 |
| 普通正文、未知斜杠输入、附加说明及首尾空白 | 正确区分完整命令与普通消息；原有文本内容不被改写 |
| 完整命令带附件 | 有明确反馈，草稿与附件保留，没有将它们送入模型作为此次命令的用户消息 |
| 主会话、普通会话与其他用户会话 | 本人当前会话可操作；主会话身份保持；越权在副作用之前拒绝 |
| 正在回复、排队输入、后台任务及维护并发 | 忙时拒绝且不停止、不排队；同会话并发不会绕过维护互斥 |
| 手动压缩与无安全有用区间 | 复用原生摘要与保留预算；分别呈现完成或无须压缩，不额外生成 Fairy 聊天回复 |
| 重置后下一次模型请求 | 不含重置前对话、旧摘要、工具结果或激活技能全文；系统装配与个人印象仍可用 |
| 重置后的记忆与技能 | 已保存记忆可按原规则检索；已启用技能目录与正文可重新加载；偏好、审核及技能包保留 |
| 重置前尚未完成的维护与学习 | 原始日志和水位可继续用于处理或恢复，不跳过或重复结算旧区间 |
| 历史、分页与多端观察 | 重置分界与旧消息来自持久事实，多端及分页可恢复，不因一次快照缺行而清除历史 |
| 后端或客户端重启 | 重置后的模型上下文保持；旧消息及重置分界仍可读取 |
| 失败、失联与同操作重试 | 不误报成功；恢复原操作结果，不把同一重试执行为第二次重置；后续新消息不被迟到重试清掉 |
| 失败后用户已经输入新草稿 | 保留可重试入口，不覆盖后续输入 |

改动相关测试先按涉及文件执行；交付前按仓库要求在最终集成状态执行后端 `npm test`、`npm run combo:verify` 和 Android `./gradlew test lintDebug`。设备交互验收单独记录，不将模型替身、单测或构建结果写成真机结果。
