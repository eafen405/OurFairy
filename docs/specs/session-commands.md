# Android 会话命令与上下文重置规格

实施状态（2026-11-10）：#343/#344/#345/#347 已合入 `integration/spec-342`；#346 已记录最终完整 Node、combo 与 Android test/lint 门禁结果。当前[协议合同](../../work/tickets/342/protocol.md)、[任务图](../../work/tickets/342/README.md)和[证据入口](../../work/implementation/evidence/342-session-commands/README.md)分别承载接口、进度与执行事实。Standards/Spec 两轴各发现 1 个 P2，已修复待最终集成复验，见 [review fixes](../../work/implementation/evidence/342-session-commands/06-review-fixes/README.md)；真机与真实模型/ASR 验收未执行。

## Problem Statement

用户在 Android 与 Fairy 长期交互时，需要主动压缩上下文，也需要在当前会话中重新开始对话。每位用户的主会话身份固定，另开或切换普通会话不会替换主会话；因此，单靠切换会话不能满足主会话重新开始的需要。

发布本规格时，输入框没有命令候选或识别反馈，直接输入 `/compact`、`/clear` 会作为普通用户消息交给 Fairy。用户无法分辨自己正在输入一条实际操作，还是仅仅给模型发了一段看起来像命令的文字。

用户希望获得快捷、明确的命令交互，同时保留原始聊天记录、印象、长期记忆和可用技能。尤其是 `/clear`，需要重置后续推理的会话上下文，而不是让 Fairy 丢失已经保存的认识和工作流。

## Solution

在当前会话的输入框上方提供命令候选。输入 `/` 时显示 `/compact`、`/clear` 两个按钮，输入 `/cl` 时只显示 `/clear`。点击候选只补全输入并保留焦点；完整命令文字变为现有主题的仪器青色，用户点击发送后才执行。普通文本继续保持原来的颜色和发送行为。

`/compact` 复用原生上下文压缩，保留会话连续性；`/clear` 在同一个会话中重置上下文，使重置前的对话原文、会话摘要和工具结果退出后续推理。旧消息仍可翻阅，并留下“上下文已重置”分界。系统提示、人格、用户身份、印象、长期记忆和可用技能继续按原有规则提供。

命令通过系统状态反馈进行中、成功、无须压缩或失败，不额外引发一轮 Fairy 聊天回复。会话正在回复、有排队消息或未结束任务时，拒绝操作并提示等待或停止后重试，不自动停止工作，也不延迟执行命令。

## User Stories

### 命令发现、补全与变色

1. 作为 Android 用户，我希望输入 `/` 就看到 `/compact` 和 `/clear` 两个快捷选项，以便不必记住或完整键入命令。
2. 作为 Android 用户，我希望输入 `/cl` 时只看到 `/clear`，以便通过短前缀快速找到目标操作。
3. 作为 Android 用户，我希望命令候选随前缀输入和删除及时更新，以便候选始终对应当前草稿。
4. 作为 Android 用户，我希望命令候选位于输入框上方，以便在现有聊天路径里发现和使用它们。
5. 作为 Android 用户，我希望点击候选只补全命令而不立即执行，以便在发送前仍能检查或修改输入。
6. 作为 Android 用户，我希望点击候选后保留输入焦点，以便补全不会打断键盘输入。
7. 作为 Android 用户，我希望完整识别的命令文字变为仪器青色，以便看出发送后将触发实际操作。
8. 作为 Android 用户，我希望手动输入完整命令也能变色，以便识别反馈不依赖我是否点击过候选。
9. 作为 Android 用户，我希望将完整命令删回 `/cl` 等前缀时恢复原色，以便颜色准确反映当前识别结果。
10. 作为 Android 用户，我希望 `/`、`/cl` 等尚未完整匹配的输入保持原色，以便候选出现不被误解为操作已经触发。
11. 作为 Android 用户，我希望普通正文中的 `/clear` 保持原色且不出现命令候选，以便讨论命令时仍能正常聊天。
12. 作为 Android 用户，我希望命令识别允许首尾空白，以便复制或输入时的空格不影响完整命令的使用。

### 识别范围、发送与会话归属

13. 作为用户，我希望首批只支持单独输入的 `/compact` 和 `/clear`，以便操作范围清楚且行为容易预期。
14. 作为用户，我希望未补全的 `/cl` 直接发送时仍是普通消息，以便未触发命令的输入延续原有行为。
15. 作为用户，我希望未知斜杠文本仍按普通消息发送，以便没有被支持的文字不会被静默丢弃。
16. 作为用户，我希望 `/clear 帮我重新开始` 这类带说明的文本仍作为普通消息，以便只有完整匹配才会执行操作。
17. 作为用户，我希望完整命令带附件时收到先移除附件的提示，并保留草稿和附件，以便附件不会被无意提交或丢失。
18. 作为用户，我希望点击发送后直接执行完整命令，以便不需要再经过一次确认。
19. 作为用户，我希望已识别的命令不作为普通用户消息交给 Fairy，以便操作由后端真实执行。
20. 作为用户，我希望命令绑定发起时的当前会话，以便切换界面不会把操作施加到另一个会话。
21. 作为用户，我希望主会话和普通会话都支持这两个命令，以便相同操作在本人会话中保持一致。
22. 作为用户，我希望命令只能作用于本人拥有的会话，以便其他用户或管理身份都不能重置我的对话。
23. 作为用户，我希望操作当前会话不影响本人的其他会话，以便各会话的上下文继续独立。

### 手动上下文压缩

24. 作为用户，我希望可以主动执行 `/compact`，以便不必等到自动压缩阈值才控制长对话的上下文成本。
25. 作为用户，我希望压缩把较早内容整理为会话摘要，以便在减少上下文的同时延续当前对话。
26. 作为用户，我希望压缩保留近期原文，以便刚讨论的细节仍可直接用于后续交互。
27. 作为用户，我希望没有安全且有用的压缩区间时看到“当前无需压缩”，以便无操作不会被误报为失败或成功压缩。
28. 作为法厄同，我希望手动压缩沿用现有压缩策略而不改动自动压缩设置，以便一次会话操作不会修改部署级配置。
29. 作为用户，我希望会话摘要与长期记忆继续分开，以便压缩不会自动把摘要写成跨会话认识。

### 同会话上下文重置

30. 作为用户，我希望 `/clear` 使重置前的对话原文退出后续推理，以便在当前会话里重新开始讨论。
31. 作为用户，我希望重置也移除旧会话摘要和工具结果的自动携带，以便旧任务不会通过摘要或工具输出继续影响新对话。
32. 作为用户，我希望重置后保持原会话身份与归属，以便主会话及其投递落点继续有效。
33. 作为用户，我希望重置前的旧消息仍留在聊天历史中，以便需要时可以向上翻阅。
34. 作为用户，我希望看到“上下文已重置”的分界，以便知道从哪里开始了新的上下文。
35. 作为用户，我希望重置后 Fairy 的系统设定、人格、身份与工具仍正常，以便重新开始对话不会变成重新配置助手。
36. 作为用户，我希望我的印象在重置后仍按原规则提供，以便 Fairy 继续保有每次互动所需的整体认识。
37. 作为用户，我希望已经保存的长期记忆仍可按原规则检索，以便重置上下文不会删除共同经历或稳定事实。
38. 作为用户，我希望已审核技能、启用偏好和技能包在重置后继续保留，以便已经建立的工作流能力不会丢失。
39. 作为用户，我希望先前激活的技能全文随旧上下文退出，并可在需要时重新加载，以便重置有效且技能仍然可用。
40. 作为用户，我希望重置不取消尚未完成的记忆维护，以便旧日志中待整理的材料仍能按原规则处理。
41. 作为用户，我希望重置不取消技能学习或其失败恢复，以便已积累的工作流证据不会因重新聊天而遗失。
42. 作为用户，我希望重置不强制先进行记忆维护或技能学习，以便这一显式操作不增加额外等待或整理流程。
43. 作为用户，我希望明确知道上下文重置不等于遗忘，以便理解旧事仍可能通过保留的记忆或后续学习被回忆。

### 忙态、执行反馈与草稿

44. 作为用户，我希望会话正在回复时拒绝上下文操作并说明原因，以便正在进行的回复不会被命令自动中断。
45. 作为用户，我希望会话有排队消息时拒绝上下文操作，以便已受理输入不会被跳过或混入重置后的上下文。
46. 作为用户，我希望会话有尚未结束的后台任务时拒绝上下文操作，以便旧任务结果不会在刚重置后未经协调地进入新对话。
47. 作为用户，我希望忙态拒绝不会自动停止回复、丢弃消息或取消任务，以便这些工作继续由我显式控制。
48. 作为用户，我希望忙时命令不被排队到工作结束后再执行，以便稍后不会出现一次我已经忘记的重置。
49. 作为用户，我希望看到压缩等操作的进行中状态，以便知道系统已经在处理命令。
50. 作为用户，我希望系统明确区分“已压缩”“当前无需压缩”“上下文已重置”和失败，以便不同结果不会混为一谈。
51. 作为用户，我希望失败提示包含具体原因，以便判断是等待会话空闲、恢复连接还是再次尝试。
52. 作为用户，我希望命令结果不额外引发 Fairy 聊天回复，以便反馈简洁且不制造新的普通对话回合。
53. 作为用户，我希望失败后仍可重试原命令，以便不必重新输入。
54. 作为用户，我希望恢复失败命令草稿时不覆盖我后来输入的新内容，以便错误恢复不会造成新的草稿损失。
55. 作为用户，我希望系统只在结果已经耐久保存后显示成功，以便请求受理不会被当作操作完成。

### 重连、重启与多端一致性

56. 作为用户，我希望同一操作的重试沿用原身份，以便网络波动不会把一次命令变成两次执行。
57. 作为用户，我希望失联后先恢复原操作结果，以便不会盲目重新执行 `/clear`。
58. 作为用户，我希望迟到的重试不会再次清掉后续新对话，以便重连恢复不会扩大原操作的影响范围。
59. 作为用户，我希望后端重启后仍按重置后的上下文继续，以便重置不只是当前进程内有效。
60. 作为用户，我希望客户端重启或重连后仍能读取旧消息和重置分界，以便历史呈现可以恢复。
61. 作为用户，我希望同一会话在多台设备上都能看到持久的重置分界，以便不同设备不会对重新开始的位置产生分歧。
62. 作为用户，我希望分页历史与实时观察遵循同一份日志，以便向上翻阅和实时更新不会产生不同版本的聊天记录。
63. 作为维护者，我希望日志序号保持追加且记忆维护、技能学习水位继续有效，以便重置不会导致材料被跳过或重复结算。
64. 作为维护者，我希望命令与新消息、投递及维护操作按同会话生命周期协调，以便并发输入不能绕过忙态判断或污染重置后的上下文。

## Implementation Decisions

### 1. 模块边界与原生复用

- 在现有聊天产品插件内承载命令受理、执行与系统状态投影，Android 沿现有会话输入入口接入；不另建通用命令平台、独立会话系统或平行聊天历史。
- 使用现有产品 HTTP/SSE 接缝、信任栅栏、凭据鉴权与会话归属检查。命令的目标用户由凭据确定，操作目标绑定发起时的会话，副作用前完成归属校验；管理身份不扩大读取或操作他人会话的权限。
- 首批命令目录固定为两项。候选过滤、完整匹配和着色复用同一客户端识别规则；服务端独立验证受限命令类型和执行资格，不信任客户端的颜色或忙态判断。
- 手动压缩直接适配已经装配的原生立即压缩能力，沿用摘要、近期原文保留、工具配对、维护互斥、持久化和恢复语义，不另写压缩算法，不引入 Typert 传输或原生命令注册表。
- 原生压缩可能调用摘要模型；不额外发起 Fairy 聊天回复不等于没有任何模型消耗。
- 没有必要为当前已激活技能新建持久状态。重置移除旧正文；原生技能目录可在后续交互重建，正文继续按需激活。

### 2. 命令识别与输入交互

- 只有单独输入且完整匹配的两条命令进入操作入口，允许首尾空白。前缀、未知斜杠文本、附加说明和普通正文继续走普通消息路径，不支持参数扩展。
- 输入 `/` 显示两个候选，输入 `/cl` 只显示 `/clear`；其他合法前缀按相同规则过滤。候选位于输入框上方，点选只替换为完整命令并保留焦点，不受理请求、不调用模型。
- 完整命令文字使用主题已有的仪器青色；未匹配输入保持现有外观。手输、补全、继续编辑和删除字符均重新依据当前草稿判定，颜色不依赖历史点击状态。
- 点击发送直接执行，无二次确认。完整命令带附件时提示先移除附件，保留草稿与附件，不把它们作为命令的用户消息提交给模型。
- 普通消息原有的附件、草稿、待确认发送与后台接收行为保留。失败后的命令恢复不得覆盖用户随后输入的新内容。

### 3. 上下文重置语义

- 保持同一个会话身份、归属及固定主会话地位；不通过创建新会话或重新绑定主会话模拟重置。
- 重置后的模型可见会话内容不再自动携带重置前的对话原文、旧会话摘要、工具结果或激活技能全文。系统提示、人格、身份、工具与印象仍由现有装配提供。
- 原始日志继续保留并追加，旧消息可翻阅、分页和按既有规则检索。系统状态投影在重置位置呈现“上下文已重置”分界。
- 仅清 Android 内存、隐藏消息或减少一次读取响应中的消息，不构成上下文重置。
- 原生会话 surface replacement 是可复用的耐久表达接缝，但不是现成的 clear API：它会插入替换节点，且系统消息存在边界约束。实施须在既有会话 surface 与维护接缝上落实重置，验证后续模型请求和冷恢复，不能假设已有可直接调用的上层重置接口。

### 4. 记忆与技能保留

- 命令路径不直接修改印象、长期记忆、技能内容、审核、启用偏好或技能包，也不重置记忆维护和技能学习的水位、冻结区间及恢复身份。
- 后台维护和学习仍可读取保留的原始日志，按既有规则处理尚未整理的材料或恢复失败任务。重置不人为触发先整理、等待整理完成或跳过旧材料的流程。
- 保留记忆与技能不代表冻结后台数据：原有维护和学习仍可能正常产生变更。长期记忆检索与后续学习可能重新带回旧事实，不能把 `/clear` 描述为遗忘或停止记忆形成。
- 个人与共有技能的可见范围、启用偏好、审核、目录及按需激活继续遵循现行技能规则，不提供第二条静默激活路径。

### 5. 忙态、并发与持久结果

- 当前会话正在回复、有排队输入或有未结束后台任务时拒绝操作，提示等待完成或停止后重试；不自动停止、丢弃或延迟执行。
- 忙态判断在后端执行前落实，并与同会话顺序执行和原生维护互斥协调。维护期间原生状态仍可能显示为空闲，不能只按这一标签判定可执行。
- 命令与新消息、投递及维护共享现有会话生命周期协调方式，保持受理和持久化顺序；不另建全局调度器。
- 使用稳定操作身份处理重试。请求受理与结果完成分别表达；成功反馈以结果耐久保存为准，结果不明时先恢复原操作结果，不以新的身份盲目重置。
- 相同操作重试不得产生第二次重置或新的分界；后续新消息不得被迟到重试清掉。并发、失败和重启后的结果须能从既有持久事实恢复。
- 状态反馈区分进行中、已压缩、当前无需压缩、上下文已重置和具体失败原因；状态呈现不伪装成用户或 Fairy 的普通消息。

### 6. 数据表达与兼容范围

- 扩展现有会话日志对命令受理、结果与重置边界的表达，并让聊天投影及 Android 协议识别对应系统呈现；旧事件不重写，日志序号继续追加。
- 不新增业务数据库表，不迁移记忆库、技能库或技能包结构。命令类型与结果状态等有限枚举在产品接口中使用数字编码，呈现层映射说明文案。
- 多端观察、断线补齐与分页读取依据同一份会话日志恢复分界和结果，不在客户端另存聊天正文或第二份重置权威。
- 具体操作入口、日志字段与公开类型由实施在现有接缝中确定；若确需扩展原生通用能力，应说明既有接缝缺口及最小补丁范围，不静默扩大为框架改造。

## Testing Decisions

### 测试接缝

用户已确认采用以下两类现有接缝；产品交互沿用已经完成的设计确认。

1. **经过认证的产品会话入口为主要行为接缝。** 经真实产品启动链路、profile 与 Loader 启动后端，从现有产品 HTTP 接口执行命令、发送后续消息、读取历史与观察结果；模型和外部网络使用确定性替身。直接捕获实际模型请求、公开状态、持久日志和重启后的结果，覆盖命令执行、权限、上下文、记忆技能与恢复，不为内部模块增加平行测试入口。
2. **Android 公共状态与页面为输入呈现接缝。** 沿现有回环 HTTP、会话公共状态及 Compose/Robolectric 页面模式验证候选、焦点、命令文字颜色、发送、附件拒绝和系统状态呈现。HTTP 无法观察真实输入焦点与颜色，因此保留这一客户端接缝，不以私有解析函数测试替代用户实际看到的行为。

### 好测试的判据

- 只断言外部可观察行为，不断言私有函数名、内部集合形状或与实现逐行对应的分支。复用既有原生压缩行为，不复制一套压缩算法作为预期。
- 用模型替身捕获重置前后真实请求。原文、摘要、工具结果和激活技能正文使用各自可辨认的材料，断言重置后不再自动携带；另行验证印象、已保存记忆与可用技能仍能按正常入口提供，避免把正常回忆误判为重置失败。
- 为每项一致性声称提供会在其失效时失败的行为检查；不能只写“已保证”、扫描源代码字符串，或仅观察客户端已经清屏。
- 原生能力如果确需修改，在其现有 Loader、维护与持久化测试接缝补相关验证，不默认增加新的产品测试面。

### 必测场景

- 候选：`/` 两项、`/cl` 单项、其他合法前缀、点选仅补全、焦点保持、手输和删除字符后的变色恢复。
- 识别：首尾空白、普通正文、未完成前缀、未知斜杠文本、附加说明以及完整命令混带附件；未匹配输入的原文保持。
- 作用域：本人主会话、本人普通会话、其他会话不受影响，以及匿名、无归属、其他用户和管理身份越权在副作用前被拒绝。
- 压缩：较长上下文、原生摘要与近期保留、无安全有用区间、失败与设置不变；没有额外普通聊天回复。
- 重置：后续模型请求、旧摘要与工具结果退出、系统装配继续有效、同会话身份不变、分界与旧历史可读取、后端重启后仍按新上下文继续。
- 记忆与技能：印象注入、保存记忆检索、技能偏好和包保留、目录重新取得、正文重新激活，以及待处理维护与学习区间继续恢复。
- 忙态与竞争：正在回复、排队消息、后台任务、原生维护竞争，以及新消息或投递与命令同时发生；拒绝不停止工作，也不延迟执行。
- 反馈与草稿：进行中、成功、无须压缩、具体失败、失败可重试，以及失败恢复不覆盖随后输入的新草稿。
- 耐久与恢复：同操作并发重试、结果不明、写入失败、服务重启、迟到重试、多观察者、客户端重连与固定截点分页；同一重试不再次重置后续对话。

### 既有先例与交付门禁

- 后端沿用真实启动器驱动的远程聊天、会话归属、稳定发送身份、重启恢复、多观察者、记忆维护及技能运行时测试模式。
- Android 沿用会话恢复、公共状态、回环 HTTP 和页面行为测试模式；不引入专用测试服务器或新的测试架构。
- 先跑改动相关测试；最终集成状态覆盖后端全量测试、版本组合验证、Android 单测与 lint。若涉及原生改动，同时完成其相关测试和既有门禁。
- 真机上的候选、键盘焦点与主题可读性另行记录设备验收；模型替身、单测、构建和设备结论分开报告。

## Out of Scope

- 首批之外的新命令、命令参数、自定义命令或动态命令发现平台。
- 在控制台新增输入框、改造目的地导航或迁移既有产品传输到 Typert。
- 删除聊天记录、清空界面历史、物理删除会话、归档主会话、替换主会话身份或改变新建会话的空会话复用规则。
- 遗忘记忆、删除印象或技能、重置启用偏好、改变技能审核和可见范围，或停止原有记忆维护与技能学习。
- 保留先前已经激活的全部技能正文常驻上下文，或新增已激活技能的持久状态库。
- 自动停止回复或后台任务、丢弃排队消息、受理后等待会话空闲再执行命令。
- 自定义压缩算法、修改部署级自动压缩策略、把会话摘要写入长期记忆，或为命令增加普通 Fairy 回复。
- 新业务数据库表、第二份聊天日志、独立命令调度平台、通用权限平台或范围外框架重构。
