# OurFairy 首版总规格：受邀多用户后端与 Android 客户端

状态：2026-10-18 修订，纳入用户确认的上游兼容及模型配置决定。2026-10-20 拓扑修订：客户端已并入 `android/`，产品组合只剩本仓库与 dsh 的锁定提交（#123）。2026-10-20 收口：传输表述与 [生态边界](../architecture/dsh-ecosystem-boundary.md) 对齐，网关只作系统配置入口，会话与活动用词对齐 [GLOSSARY](../../GLOSSARY.md)。实施进度与验收证据从 [CONVENTIONS](../../work/implementation/CONVENTIONS.md) 进入。

## Problem Statement

法厄同与受邀代理人需要在手机上使用同一个 Fairy：各自拥有独立会话与私有内容，同时能够通过公有、群组文件空间协作，并让 Fairy 向指定用户交付文字和文件。手机断线、切后台或被系统回收后，后端执行和已经保存的内容需要继续成立，恢复连接后能够接续阅读。

现有 rikkahub 客户端（现已内联在 `android/`）的执行、会话权威和个人模型配置，以及 dsh 的单操作者入口，不能原样组成上述产品。旧 Fairybot 提供了可复用行为和局部实现，但本轮不继承其集中宿主结构，也不默认保留全部旧功能。长回复显示持续落后、流式期间滚动卡顿、任务与通知状态不一致，是首版必须覆盖的体验问题。

三张 wayfinder 地图已经明确产品范围、后端装配和实施路线。本规格将分散的最终决议汇成可供拆票和 implement-spec 执行的统一要求；规划完成不表示产品已经实现或验收通过。

## Solution

提供一个内联在 `android/` 的 Android APK。网关是法厄同的系统配置入口，只管理共用供应商、模型与 ASR 连接配置；法厄同与代理人一样在普通会话里对话。所有模型执行、工具和权威会话数据位于共用后端。每个会话永久归属于一位用户，每位用户有固定主会话。管理身份、已知用户编号或会话标识均不授予他人个人内容的访问权。

后端基于 dsh 的显式插件装配，按会话和执行传递用户范围，复用已有模型、工具、持久化和任务能力。Fairy 可读取当前用户获准的文件空间、执行联网脚本、查询本人其他会话，并将明确指定的文字和文件保存到其他用户主会话。投递呈现为收件方的普通 Fairy 消息，通知后等待用户响应，不启动收件方推理。

客户端提供多会话交互、Fairy 视觉表现、附件、硅基流动 ASR 输入、长任务活动卡和系统通知。每会话的活动统一合并 Fairy 执行、同会话未结束的后台任务、实际待处理结果报告及投递输出。法厄同统一配置共用供应商和模型；首版初始共用选择由 bundle 的 `agent-default-model` 行声明（见 [backend/v1-bundle](../../backend/v1-bundle/README.md)），官方 DeepSeek 路线保留为可切换的备选。普通图片及 PDF 扫描页按需读图的要求保留；PDF 文字按页提取并保留页码。

手机断线不取消后端执行。客户端恢复时补齐内容与状态，按会话合并积压提醒；流式期间可先显示原始纯文本，结束后必须完整呈现格式。首批验收设备为 vivo S50，自用 APK、不依赖 Google 推送，后台即时提醒受系统及厂商限制。

## User Stories

以下使用“作为角色，我希望行为，以便收益”的统一格式；编号供后续实施票引用。术语以 [GLOSSARY](../../GLOSSARY.md) 为准；下文故事正文沿用实施时确认的措辞，其中“在网关中对话”指在网关入口维护共用配置（网关只提供系统配置），“保持激活”指该会话仍有活动。

### 身份、入口与系统配置

1. 作为法厄同，我希望生成邀请码，以便邀请指定的人加入。
2. 作为受邀代理人，我希望通过邀请码注册并登录，以便拥有自己的身份和会话。
3. 作为用户，我希望拥有按注册顺序分配的简短用户编号，以便 Fairy 能明确指定投递对象。
4. 作为法厄同，我希望自己的用户编号为 1，并由 Fairy 称呼为“主人”，以便身份与既定角色一致。
5. 作为用户，我希望在同一个 APK 中看到符合自身身份的入口，以便无需维护不同客户端。
6. 作为法厄同，我希望在网关中对话，管理共用供应商、模型和 ASR 连接配置，并让所有会话从下一轮回复采用选定模型，以便维护系统且不打断正在执行的回复。
7. 作为代理人，我希望通过对话使用 Fairy，以便不必接触系统管理配置。
8. 作为用户，我希望系统管理者也不能凭管理身份读取我的个人内容，以便管理与个人隐私分别受到约束。
9. 作为用户，我希望共享模型配置时仍保持自己的上下文独立，以便他人的对话不混入我的会话。
10. 作为用户，我希望切换账号或重新连接后内容仍属于正确身份，以便旧请求和迟到事件不会显示到另一个账号。

### 会话、检索与执行

11. 作为用户，我希望创建、列出并切换自己的多个会话，以便分开处理不同事情。
12. 作为用户，我希望每个会话始终归属于创建它的用户，以便重启或恢复不会改变访问范围。
13. 作为用户，我希望拥有固定主会话并能随时返回它，以便找到 Fairy 向我投递的内容。
14. 作为用户，我希望新建或使用其他会话不改变主会话，以便投递入口保持稳定。
15. 作为用户，我希望从手机向后端 Fairy 发送消息并接收回复，以便执行能力不受手机本地运行环境限制。
16. 作为用户，我希望应用切后台或网络断开后后端继续执行，以便工作不会因连接变化被取消。
17. 作为用户，我希望显式停止当前回复，以便控制本轮处理，而不误停独立运行的后台任务。
18. 作为用户，我希望重新连接后恢复已经保存的历史和当前状态，以便接着阅读而不重复或漏掉内容。
19. 作为用户，我希望 Fairy 能搜索我自己的其他会话，以便找回相关讨论。
20. 作为用户，我希望搜索结果带会话标识、原事件位置和命中消息片段，以便继续准确读取上下文。
21. 作为用户，我希望 Fairy 按指定事件区间读取本人会话并排除工具结果，以便获取相关对话内容。
22. 作为用户，我希望他人即使知道我的会话标识也无法读取、控制或订阅它，以便编号不会成为访问凭据。
23. 作为用户，我希望 Fairy 保持部署提供的人格与回复风格，并与外部材料区分来源，以便聊天中的改写要求、文件或检索内容不会变成系统配置。

### 空间、文件与群组

24. 作为用户，我希望 Fairy 能使用我的私有空间、公有空间和我所属的群组空间，以便在获准范围内工作。
25. 作为用户，我希望公有空间的文件可以直接共享使用，以便协作时无需逐文件设置权限。
26. 作为用户，我希望通过对话和交付物参与文件工作，以便无需直接管理后端空间目录。
27. 作为法厄同，我希望通过与 Fairy 对话创建群组并指定群主，以便组织共享文件范围。
28. 作为群主，我希望通过 Fairy 添加和移除自己群组的成员，以便管理协作范围。
29. 作为普通群组成员，我希望只有有资格的管理者能改变成员关系，以便其他成员不能借工具或提示词取得管理权。
30. 作为用户，我希望文件工具与脚本执行遵守同一空间范围，以便换一种工具也不会绕过权限。
31. 作为用户，我希望 Fairy 能联网并安装工作所需依赖，以便完成实际任务，同时保持文件范围约束。
32. 作为用户，我希望改变工作目录不会扩大可访问范围，以便目录设置不会影响权限规则。

### 投递与附件

33. 作为用户，我希望让 Fairy 向指定用户编号投递文字和可选文件，以便明确交付我选择的内容。
34. 作为用户，我希望一次明确投递无需再次进行分享审批，以便授权后的交付能够完成。
35. 作为发送方用户，我希望投递只包含指定内容，以便不会隐式复制本会话其他上下文。
36. 作为收件用户，我希望投递进入固定主会话并显示为普通 Fairy 消息，以便直接阅读和继续回应。
37. 作为收件用户，我希望投递本身不启动新的推理，以便 Fairy 等待我的响应。
38. 作为收件用户，我希望以后回复时 Fairy 能看到已收到的投递历史，以便对话能够延续。
39. 作为用户，我希望网络重试或进程故障后的恢复不会重复插入同一次投递，以便消息历史保持一致。
40. 作为用户，我希望投递附件准备失败时不会被告知完整送达，以便送达结果可信。
41. 作为用户，我希望系统提醒失败不会撤销已保存消息，以便重连后仍能读到它。
42. 作为用户，我希望选择并上传附件，在取得有效引用后发送，以便手机文件能交给后端处理。
43. 作为用户，我希望有资格的收件会话能下载收到的原始文件，以便获取完整交付物。
44. 作为用户，我希望不能用其他人的附件引用读取文件，以便存储去重不会变成越权通道。

### 后台任务与活动

45. 作为用户，我希望 Fairy 启动长脚本后可以继续处理对话，以便无需等待整个任务结束。
46. 作为用户，我希望通过活动卡及详情查看任务状态和输出，以便了解进展。
47. 作为用户，我希望单独停止后台任务，以便结束指定工作而不混淆“停止回复”。
48. 作为用户，我希望任务结果回到原会话，以便工作和结果保持关联。
49. 作为用户，我希望同会话仍有后台任务时保持激活，以便状态反映仍未完成的工作。
50. 作为用户，我希望任务结束与实际结果报告连成同次活动，以便不会因短暂状态间隙重复提醒。
51. 作为用户，我希望不同会话独立计算活动，以便一个长任务不阻止其他会话结束时提醒。
52. 作为用户，我希望任务输出缺失或服务器重启后的未知状态被如实说明，以便不误以为日志完整或任务已成功。

### 通知与恢复

53. 作为用户，我希望应用在前台时统一不弹系统通知，以便使用任何页面时都不被重复打扰。
54. 作为用户，我希望后台静默会话收到投递并输出时提醒一次，以便及时注意新内容。
55. 作为用户，我希望同次活动结束时不再次重复提醒，以便投递的输出和静默不会造成双重打扰。
56. 作为用户，我希望后台工作最终结束且本次活动尚未提醒时收到一次通知，以便知道结果可以查看。
57. 作为用户，我希望重连后每个会话的积压合成一条提醒，以便不会逐条重放历史通知。
58. 作为用户，我希望不同会话使用独立通知位置，点击后进入对应会话，以便快速定位内容。
59. 作为用户，我希望第一次启用后台提醒时得到必要设置指引，拒绝后仍可从设置进入，以便自主决定且不被反复弹窗。
60. 作为用户，我希望能看到接收状态及系统限制，以便理解锁屏、断网或进程停止时提醒可能延迟。
61. 作为新设备用户，我希望首次同步旧历史后建立当前通知基线，以便不会为全部旧消息补发通知。
62. 作为用户，我希望普通断线沿有效消费记录补齐，而记录无法恢复时采用明确的初始化规则，以便恢复行为可预期。

### 输入、PDF 与呈现

63. 作为用户，我希望用语音转写得到可编辑文字草稿，以便核对后再发送消息。
64. 作为用户，我希望取消、识别失败或切换输入归属时不会把迟到文字写入错误草稿，以便输入内容可靠。
65. 作为用户，我希望语音识别可用性和错误被清楚反馈，以便不会把无密钥、超时等情况当成成功转写。
66. 作为用户，我希望 Fairy 按页读取文字型 PDF 并保留页码，以便定位回答所依据的原文。
67. 作为用户，我希望扫描页、图表和复杂排版可以按需转为页面图片读取，以便 PDF 阅读覆盖已确认范围。
68. 作为用户，我希望长 PDF 按需选择页面并保留原件，以便控制处理成本并继续追问或下载。
69. 作为用户，我希望损坏、加密或超限文件的读取结果明确，以便不把不完整内容误认为全文成功。
70. 作为用户，我希望保留 Fairy 眼睛动效、回复面板及视觉方向，以便客户端保持熟悉的体验。
71. 作为用户，我希望在设备本地调整深浅色和字体显示，以便阅读符合自己的偏好。
72. 作为用户，我希望长回复不会越长越落后，也能在流式期间顺畅滚动，以便及时阅读已经收到的内容。
73. 作为用户，我希望输出期间可先阅读原始纯文本，而结束后完整呈现代码、表格、公式和 Markdown，以便及时性与最终格式都得到满足。
74. 作为用户，我希望停止、错误和恢复历史时也保留完整已收正文并正确收尾，以便不丢最后内容或永久停在未完成格式。
75. 作为用户，我希望流式转完整格式时阅读位置连续，以便不会突然跳动、闪空白或重新播放旧内容。

## Implementation Decisions

### 1. 权威、范围与领域规则

- 本规格继承三张已完成地图及其最终 resolution；较晚的明确决定优先。研究中的候选方案、早期交接的待定项和旧项目默认值不自动成为首版要求。
- 用户由法厄同邀请加入；法厄同编号为 1，其余按注册顺序使用简短编号。邀请码用于注册加入，不等同于用邀请码代替完整登录认证。
- 单个会话只有一位永久所属用户；每位用户有固定主会话。共享后端及模型配置不共享个人会话上下文。若暴露原生会话派生入口，必须继承归属；未适配的入口不对外开放。
- 法厄同有系统管理权限，但不因此获得他人个人内容或未加入群组文件的访问权。群组表示文件空间范围，不是群组聊天。
- 一个 Fairy 服务多人，部署设定与执行上下文分别由所属模块生产；人格与回复风格不是用户通过聊天指令可改的配置，外部材料不提升为部署指令。角色内容、提示来源检查与授权规则分别落实，不以提示词叮嘱代替文件或会话权限，也不宣称模型具有绝对不可被提示影响的保证。

### 2. 装配、复用与模块责任

- 使用一套 dsh 显式产品 profile，通过受支持的启动与配置装配机制连接能力。不得整套继承包含排除功能的默认组合；npm 接口依赖不等于运行时启用相应产品能力。
- 上游兼容的取舍遵循 [ADR-0001](../adr/0001-upstream-extension-policy.md)：优先跟进官方更新，复用已有接口，按具体缺口及维护成本选择必要扩展。升级时核对已被上游覆盖的能力，再决定产品补丁的保留或收缩。
- 直接复用 Agent 循环、工具注册、系统提示及会话投影机制、官方模型 provider、现有进程超时/取消，以及 jobs 的任务句柄与输出控制；行集合以 [backend/v1-bundle](../../backend/v1-bundle/README.md) 为准。会话归属、正式事件、格式、查询和单操作者入口需要原生适配。
- 文件工具及 sandbox 的 Interface 复用 dsh；具体权限和进程限制以旧 Fairybot 的局部实现为基础适配。必须证明实际读取及执行遵守空间规则，不能仅凭替换一个 provider 宣称完成隔离。
- 产品模块包括身份、会话、空间权限、文件/附件、脚本执行、投递、客户端接入/同步、通知、ASR 和 PDF 阅读。模块维护自身规则，启动装配只连接依赖。职责划分不强制一模块一个包，更不允许用一个万能管理模块承接所有规则。
- 运行时选用会话日志与 checkpoint、可重建 SQLite 查询、不可变本地附件、文件/目录工具、受限脚本、jobs 及其控制工具。查询启用方式、数据目录与模型路由显式配置；查询插件本身的启动默认值与上层默认组合覆盖不同，不沿用“它天然关闭”的旧表述。
- 初始共用选择由 bundle 的 `agent-default-model` 行唯一声明（见 [backend/v1-bundle](../../backend/v1-bundle/README.md)），复用 dsh 自带的 `minimax-cn` 供应商（端点、协议、模型元数据）与 `MINIMAX_CN_API_KEY` 凭据引用；上下文、输入能力与思考深度随该行声明。供应商与模型名用连字符 id，带空格的别名会被服务端静默降级到其他模型。官方 DeepSeek 路线保留为可切换备选；自定义供应商和模型同样复用 `@deepseek-ai/dsh-llm-pi-ai` 的路由、协议、端点、模型清单和能力定义。模型 API 名称可能指向官方更新版本，验收记录实际能力。
- 共用模型选择对所有会话生效：每个会话从下一轮回复开始采用新选择，正在执行的回复及其中的工具调用、模型续请求继续使用原模型。既有会话、冷恢复和多会话并发均需覆盖。客户端断线不改变这项规则。
- 供应商、模型定义及共用选择复用 dsh profile/settings 的持久化；模型及 ASR 凭据由后端管理，优先复用原生凭据机制。组合中的初始模型声明与运行时已保存的选择职责不同，启动不能覆盖法厄同已保存的选择。手机管理入口仅暴露已授权字段及操作。
- 会影响在途回复所用路由的端点、协议或模型定义修改、删除、重载请求，返回明确的在用状态，由法厄同在回复结束后重试；接线须覆盖与新回复开始的并发。以实际受影响路由判定范围，整插件重载覆盖其全部路由。修改共用选择按前述下一轮规则生效。

### 3. 数据、身份与持久化

| 数据 | 权威及责任 |
| --- | --- |
| 会话归属、正文及事件 | 适配后的 dsh 会话日志；归属随会话头永久保存 |
| 会话搜索数据 | 可重建的独立 SQLite 派生索引 |
| 用户、邀请码 | 业务 SQLite，由身份模块维护 |
| 群组与成员、空间关系 | 业务 SQLite，由空间模块维护 |
| 固定主会话定位 | 会话模块按用户编号确定主会话标识，并核对原生日志中的归属；沿用现有实现 |
| 投递身份、协调状态及通知恢复依据 | 业务 SQLite，由投递/通知各自维护 |
| 附件原始内容 | 不可变内容寻址存储；存储去重不表示访问资格 |

- 会话创建从可信登录身份确定归属；客户端和模型不能自选归属。执行从既有 Agent/Session 取得同一身份，不引入可变进程级“当前用户”。
- 列表、搜索、历史、订阅、发送、恢复、停止及附件/任务入口在副作用或返回内容之前核对资格。live 命中同样检查；cold 恢复过程可能修复日志，不能到恢复后才做授权。
- 搜索先限制到当前用户再排名和截断；区间读取独立核对目标归属。搜索提供会话标识、匹配事件位置和命中消息片段，片段长度门槛由 `tests/conversation-search.test.mjs` 断言；区间读取排除工具结果并保留原事件位置。端点、其他内容投影和总输出预算由实现明确并测试。
- 查询索引、主会话关系与协调记录不能成为第二份独立会话归属权威。查询库重建不影响业务数据。
- 归属和正式事件贯穿创建、恢复、物理编解码、格式/catalog、消息/surface、模型请求投影、查询及所有必要消费者。改变公共类型时维护消费者编译与兼容，不能只注册一个投影插件。
- 采用明确的正式格式演进规则；已发布旧格式不得原地改写并伪称兼容。缺失可靠归属的旧日志拒绝接入或经过有依据的显式转换，不默认用户 1；本规格不要求自动迁移旧产品数据。

### 4. 空间、群组、附件与执行

- 当前会话用户可使用本人的私有空间、所属群组空间和公有空间。公有文件直接共享，无逐文件权限配置。空间实际读写由 Fairy 执行，用户通过对话和交付物参与。
- 法厄同通过对话创建群组并指定群主；群主通过对话添加/移除本群成员，不另建群组管理页面。工具可见性按角色提供，实际变更仍核对该用户当前对目标群组的资格；其他群组的群主身份不扩大权限。
- 文件实际访问与进程启动各自落实相同空间规则。目录设置、工具以外的目录检查、附件物化、后台任务启动和 full-access 等路径不能绕过用户范围。联网与安装依赖允许，按用户分别安装依赖环境不是产品要求。
- 上传成功产生可发送的有效引用；发送时复核完成状态和归属资格。下载、模型文件句柄、工具读取及投递分别核对可访问性；不得将全局附件存储暴露为任意用户的读取根。
- 投递可共享不可变内容以减少复制，但必须形成收件会话的引用资格。下载保留原始交付物，模型用的归一化图片或 PDF 派生页面不替代原件。
- 保持原生脚本执行的超时、取消与输出能力；真实受限进程验收是必要条件，工作目录或模型工具描述本身不能证明隔离。

### 5. 投递、后台任务与活动

- 投递工具接收目标用户编号、指定文字和可选文件，内部定位固定主会话。工具调用本身表达指定内容的投递授权，不增加二次分享审批；投递调用方不获得收件历史读取能力，也不隐式复制来源会话其他内容。
- 投递正式保存为普通 Fairy 发言，保留真实来源、稳定投递身份及附件引用；需要说明来源时由正文表达，不新增“代为转达”标签。送达不启动收件方推理，后续回复时进入既有模型历史。
- 正式投递事件与模型现场生成有不同来源，不能伪造模型 turn/step/stream。官方 provider 的 assistant 内容不能原样包含文件/图片时，使用合法、保留来源的文字句柄与获准工具读取；界面仍保持普通 Fairy 消息。
- 同会话共用一个写入生命周期：live 使用已有 Session/writer，cold 取得协调后的独占写句柄，不为投递创建 Agent 推理。先落盘再确认/产生通知依据。
- 稳定投递身份在重试前确定，目标和内容保持一致。持久日志中的该身份是送达事实，业务库按其协调恢复；跨 JSONL 与 SQLite 不假定天然原子。附件准备失败不能报告完整送达，通知失败不撤销正文。
- jobs 支持长脚本与对话并行；忙时结果进入原 Agent 后续上下文，空闲时按所选完成反馈配置报告，归属始终为原会话。手机连接变化不销毁 Agent 或取消任务。
- 任务采用活动卡与详情，可查看输出、停止指定任务；停止回复和停止后台任务是不同操作。任务输出有保留窗口，缺口明确显示；服务器重启后不承诺进程续跑，未知任务状态不伪装成运行或成功。
- **活动按会话合并**：Fairy 正在执行、同会话任务仍在运行或停止中、实际待处理结果报告、投递输出，任一仍存在时该会话仍有活动；全部完成后该会话不再有活动，会话何时退出热状态按 [热会话／静默会话](../../GLOSSARY.md) 的定义。长任务未结束时，中间回复完成不另提醒，其他会话独立。
- 合并状态由一个模块维护并提供给呈现和通知。原生 Agent 运行状态与 jobs 状态不同；只看是否正在出字、模型 attempt 或单个 turn/end 均不充分。任务结束与实际报告衔接避免短暂静默造成重复活动；没有报告、取消或失败时明确结算，不为不存在的工作永久保持活动。断线或未知状态不直接当作静默会话。

### 6. 客户端共同接口、恢复与通知

- 后端提供可信身份、授权后的会话/任务/附件操作与持久事实；客户端会话同步模块提供观察会话、发送、补历史、双停止和观察任务输出，内部维护消息身份、重连归并、活动及消费记录。页面不各自解释原生事件。
- 产品传输是自建 SSE：`/chat/observe` 持续输出，断线补齐用 `/chat/read` 与 `/chat/page`；未接入的原生接缝与重新评估条件见 [生态边界](../architecture/dsh-ecosystem-boundary.md)。观察流的历史截点、活动 attempt 基线及向后分页共同支持恢复；历史上界不是增量 after 游标。
- 区分已观察事件与已保存、完整应用的前缀。原生事件可能先发布后落盘；只有实际 writer 屏障成功且所需范围补齐后，才能确认并推进持久消费点。流式正文可及时展示，不能因此提前宣称可恢复。
- 重连固定补齐目标、对账重叠、独立归并实时尾部，并保留 active attempt 累计内容。原始增量有序无损，只有累积完整展示快照可覆盖过时版本；已提交投递不与正在生成的最后一个气泡混淆。
- UIMessage 与 dsh Message 不一一对应，必须通过正式消息投影适配。客户端缓存不成为后端日志的替代权威。账号、连接及会话切换使旧回调失效，避免写入错误视图。
- 应用在前台时统一不弹系统通知，与当前阅读哪个会话无关。
- 应用后台、静默会话收到投递并输出时提醒一次，随后静默不重复；后台工作最终结束且本次活动未提醒时提醒一次。进行中的投递并入当前活动，不让投递、生成、jobs 分别制定提醒政策。
- 断线恢复先补齐内容和当前状态，再把各会话尚未提醒的积压合成一条通知，不逐次重放历史状态变化。通知位置按会话稳定且相互独立，点击定位目标会话并核对当前账号资格；摘要可使用最近内容预览，无需额外模型调用。
- 首次设备或通知消费记录无法恢复时，同步历史后建立当前基线，旧历史可读但不补发全部旧通知；有有效记录的普通断线仍补积压，能恢复记录时先恢复。提醒消费位置与已读位置独立。
- 本地通知发布与消费记录不存在天然原子事务；按事件/活动去重并验证崩溃窗口，不宣称严格恰好一次。
- 首版采用自用 APK 前台接收服务、后台系统通知和持久补取。首次启用引导必要通知/后台设置，拒绝后保留入口与接收状态说明，不反复弹窗。进程回收、Doze、网络和厂商策略可能延迟提醒；用户强停后不承诺连接继续，正式厂商推送不作为当前已具备通道。

### 7. Android 功能取舍、ASR、PDF 与呈现

- 一 APK、同一导航结构按身份展示入口。保留对话、多会话与固定主会话导航、主动消息接收、通知定位、Fairy 眼睛动效/回复面板、设备本地深浅色与字体偏好、附件及语音输入。
- 法厄同保留共用系统配置和邀请码生成入口；代理人使用对话入口。群组管理经对话完成。身份可见性不是后端授权的替代；后端业务数据库不是客户端直接操作数据库的入口。
- 法厄同网关管理共用供应商、模型及现有 ASR 连接配置，复用相应后端配置定义和校验，分别反馈保存结果、可用性及生效时机。插件安装、启停和装配由部署维护。管理资格不授予原生 owner 入口的全部能力或个人内容访问权。
- 复用 Fairy 视觉资源与设计方向、内联客户端已有的列表和富文本能力；实现按实际类型和生命周期适配，不把视觉继承当作旧客户端整套可直接迁移。
- ASR 使用硅基流动，由后端读取 `VOICE_API_KEY`。录音经认证的后端代理得到文字后回填可编辑草稿，ASR 本身不自动提交聊天或触发 Agent。取消/失败及输入归属变化处理迟到结果，不自动归档每次录音。
- ASR 模型与限制为部署配置；旧硬编码型号不在当前公开枚举不等于账号实测必然失败。采用当前支持的配置并验证录音容器/账号，不能以静态源码代替真实可用性。旧时长、并发和超时值不自动成为本规格产品承诺。
- PDF 支持文字提取及扫描页/图表按需读图。后端提供页数、已有目录或少量样本，再按问题选择页码，文字保留页码，指定页渲染为图片并走现有官方视觉通路。原始 PDF 保留用于下载、投递和继续追问。
- PDF 解析/渲染模块内部处理资格、资源预算和派生产物；具体维护库按平台、构建及样本验证选择。损坏、加密、超限、截断与无文字结果明确，复杂版面识别不承诺完美，未读页面不声称已理解。不添加第三方 OCR 或音视频解码服务作为默认依赖。
- 流式期间可先显示含格式符号的纯文本，结束后必须完整呈现 Markdown、代码、表格和公式。原文始终保留，最后增量不可丢失，即使最后只变化结束状态也要触发最终格式；停止、错误及恢复历史同样正确收尾，临时断线不当作结束。
- 复用已有无损累积、最新完整快照、后台解析、稳定消息身份、缓存和用户滚动优先机制。旧工作不能覆盖终态，格式转换时保持阅读位置；不能让界面持续追赶过时队列、闪空白或重放内容。性能复杂性留在接收/呈现模块，不散布到页面。
- 旧 16 ms 发布节奏或动画参数不是新产品延迟指标；是否进一步拆块布局由实测决定。目标 vivo S50 release 构建分别记录接收到呈现延迟、帧耗时/卡顿比例、积压和内存。

## Testing Decisions

### 主要测试接缝

用户已在本轮确认采用以下接缝。

首选已经确定的**经过认证的产品会话 Interface**作为最高层行为入口：通过真实 profile/Loader 装配的应用发送、读取、投递、停止、订阅和恢复，观察返回结果、持久历史、模型可见输入及客户端可消费事件。真实会话日志、业务 SQLite、查询与附件实现贯穿该路径；只替换云模型、ASR、时钟/网络故障等外部或不确定输入。

这个接缝覆盖大部分产品规则，不为每个内部类额外制造测试专用接口。必要的补充限定在实际变化的接缝：原生格式/恢复与单写者兼容、真实文件/进程权限，以及 Android 接收公开状态后的 UI/通知行为。文件与 sandbox 的安全保证必须运行真实受限进程验证，不能仅用桩返回“拒绝”。

Android 从共同会话投影和平台 Adapter 验证前后台、通知、任务控制、输入归属和最终呈现；先使用确定的网络/平台替身，再以构建产物和 vivo S50 验证平台行为。新增测试接缝以调用方已有 Interface 为先，避免为了测试搭建另一套运行模型。

### 测试原则与模块范围

- 测试用户、模型或真实调用方可观察的行为及有意义失败，不断言私有方法调用次数、内部类布局或测试专用实现细节。
- 覆盖身份、会话/检索、空间、文件/进程、投递、同步/活动、通知、ASR、PDF 和消息呈现模块；按职责观察结果，公共入口验证组合，必要原生契约测试验证格式和受限执行。
- 对 dsh 的产品可见插件保留真实 Loader/应用组合检查；不能只手工拼插件并由此宣称发版 profile 可用。公共事件/类型变更覆盖必要消费者及原生要求的回放/兼容检查。
- 故障测试在真实持久化、进程、网络、provider 等已有边界注入可控失败；重启后从公开读取/恢复路径检查结果，不直接修数据库制造通过。
- 并发测试拥有自己的用户、目录、端口、进程及销毁过程；账号、会话、连接代际和幂等身份都必须可区分。
- 性能验收在实施票中固定可复现的工作负载及据基线制定的门槛，记录相同条件下的结果；不得把旧调度常量当作用户已确认的延迟指标，也不得用构建成功代替呈现性能证据。
- 仅运行与改动有关的必要检查及所属仓库要求的门槛；报告实际命令、产物、结果和未执行条件。替身测试、真实云服务、构建、模拟器及真机证据分别记录。

### 验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 法厄同配置网关 | 自定义供应商、模型和 ASR 配置可验证、保存及恢复；普通代理人直调被拒绝；凭据按后端职责管理，无效配置明确反馈 |

| 投递 live/cold/生成中 | 单次有序保存、真实来源、正确收件资格；正在生成的回复不被投递气泡覆盖；投递不触发收件推理，后续用户回复能读到投递历史 |
| 投递重试及故障 | 同身份不重复消息；附件失败不完整送达；flush 失败不提前确认；日志保存后业务记录未更新可恢复；通知失败保留正文 |
| 回复、jobs 与报告并行 | 双停止独立；断线继续执行；任务卡及输出缺口真实；任务结束到报告不误开第二次活动，不存在的报告不永久保持活动 |
| 多会话活动及通知 | 一个会话长任务不阻止另一个提醒；中间回复完成不结束仍有任务的会话；后台静默会话收到投递提醒一次，结尾不重复；前台应用统一抑制 |
| 长断线与并发实时尾部 | 固定截点补齐，无原始增量丢失/重复，活动 attempt 前缀正确，持久消费点不越过未保存或未补齐范围 |
| 首次设备与消费记录恢复 | 新基线前历史可读但不补旧通知；有效旧记录补积压，每会话合并；账号切换/迟到事件不污染其他用户 |
| 附件生命周期 | 未完成、过期或他人引用不能发送/读取；正确收件人能下载原件，哈希相同不产生公共读取资格 |
| ASR | 无密钥、拒绝、空结果、取消、迟到回调、超时与限流结果明确；成功为可编辑文字，未自动发聊天；真实账号与录音容器单独联调 |
| PDF 与官方视觉 | 文字/扫描/混合页及图表可按页读取，页码正确，原件可下载；损坏/加密/超限结果明确；图像工具结果经所选官方 provider 实际可用 |
| 流式及最终格式 | 长文本/代码/表格/公式与跨段引用；最后增量和纯状态终态不漏；停止/错误/恢复历史均收尾，旧结果不覆盖终态，滚动位置连续 |
| vivo S50 release | 前后台、锁屏、网络恢复、普通回收与用户停止按能力边界记录；测帧耗时、接收至呈现延迟、积压与内存，不用冷启动基准替代 |

## Out of Scope

- 首版子代理、记忆/私密记忆分类、印象蒸馏、表达学习、定时任务、技能能力及通用主动任务策略；后台 jobs 不等于定时任务。
- 个人模型/凭据选择、未来 Web 或 React 网关、手机嵌入 Web server、agent 操作手机。
- TTS、图片/视频生成、音视频附件内容理解；硅基流动 ASR 语音输入独立保留。
- 媒体备份、S3/WebDAV、QR 扫码分享邀请、独立任务中心、独立群组成员管理页面及未获采纳的 fork 原有功能。
- 自动迁移旧 Fairybot/rikkahub 用户数据、无可靠归属的旧日志自动接管、后台进程跨服务器重启自动续跑、所有任务输出永久完整保存。
- 正式厂商推送上线、应用商店发布，以及所有后台状态即时必达或系统通知严格恰好一次的保证。
- 新建通用权限平台、万能上下文/管理层、第二套权威聊天日志、独立人格输出审查系统或第三方 OCR 服务作为默认方案。
- 生产部署、用户数据迁移执行及正式发布操作。本规格要求完成代码、可复现构建/集成和目标设备验收；生产操作另按明确部署范围执行。
