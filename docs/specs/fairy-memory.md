# Fairy 记忆与上下文治理规格

## Problem Statement

用户希望 Fairy 记住偏好、共同经历和当前事实，但不希望这些内容随着会话无限进入模型上下文。持续累积会增加 token 开销、缩短会话可用寿命，也会让过期事实与当前认识混杂。单纯增加一个向量检索库不能解决这些问题，dsh 原生的会话压缩也不能代替长期记忆。

OurFairy 当前没有长期记忆或印象插件，原生压缩行尚未装配。旧 Fairybot 提供了记忆、印象与离线蒸馏经验，但其集中宿主、按用户分区和重复蒸馏方式不符合本次已经确认的行为。多用户场景下，Fairy 需要保持连续的记忆和社交分寸，而不是在切换会话后按用户失忆；与此同时，普通检索不应把私密记忆意外带进上下文。

法厄同还需要独立控制自动压缩和记忆维护节奏。数值设置不能绑在模型配置或一组平铺参数里，客户端应同时提供滑块和直接输入。

## Solution

新增一个 `@ourfairy/dsh-memory` 产品插件，统一承载长期记忆、印象和单会话增量维护。长期记忆由 Fairy 通过一小组增删查改工具使用；普通与私密记忆共用工具，通过 `is_private` 区分。印象每位用户一份，直接注入对应用户的模型上下文，用户只能查看本人的印象，Fairy 可在用户明确要求时修改。

记忆维护在每个源会话独立进行。新增闭合用户回合达到动态门槛且源会话静默时，一个使用轻量模型、只有记忆工具的子会话读取封口区间，自行决定新增、更新、删除或略过。源会话与维护子会话并行，后续消息归入下一区间。主 Fairy 主要在用户明确要求时立即新增记忆。

上下文压缩直接复用 dsh 原生能力。新增一个与模型配置无关的“自动压缩触发阈值”绝对 token 设置，由 dsh 在模型容量允许范围内执行；不为 OurFairy 另写压缩算法。自动压缩、记忆维护和印象分别负责会话延续、长期记忆和每次互动所需的整体认识，工作流经验继续属于 skill 系统。

## User Stories

### 长期记忆与使用边界

1. 作为用户，我希望明确要求 Fairy 记住一件事时她能立即保存，以便不必等待后台维护。
2. 作为 Fairy，我希望跨会话保留具体事实和共同经历，以便延续与用户的关系和工作。
3. 作为 Fairy，我希望记忆来源指向支撑当前内容的会话，以便需要时核对归属和原始依据。
4. 作为 Fairy，我希望新增和内容编辑时由系统确定来源会话与归属用户，以便模型不能自行伪造归属。
5. 作为 Fairy，我希望每条记忆只有一份，以便不同会话不会出现分别更新的副本。
6. 作为 Fairy，我希望新记忆默认进入普通层，以便只有经过有意识的动作才形成私密记忆。
7. 作为 Fairy，我希望普通检索只返回普通记忆，以便日常回答不会被私密内容意外污染。
8. 作为 Fairy，我希望显式传入 `is_private` 后使用同一组工具处理私密记忆，以便增加有意操作的成本而不翻倍工具数量。
9. 作为 Fairy，我希望用一个 `memory_switch` 在普通与私密之间切换单条记忆，以便改变层级而不产生副本。
10. 作为 Fairy，我希望发现记忆过时时直接删除，以便当前认识不与失效内容混合。
11. 作为 Fairy，我希望删除后的整数编号不再复用，以便旧查询结果永远不会指向一条新记忆。
12. 作为用户，我希望通过对话询问、纠正或要求删除长期记忆，以便不需要理解数据库结构。
13. 作为用户，我希望客户端不开放长期记忆全库编辑器，以便对记忆的查询和修改仍经过 Fairy 的判断。

### 印象

14. 作为用户，我希望每位用户都有独立印象，以便 Fairy 在每次互动中保持对我的持续整体理解。
15. 作为用户，我希望只能查看本人的印象，以便管理身份、他人编号或会话标识都不能扩大我的访问范围。
16. 作为用户，我希望通过对话要求 Fairy 纠正印象，以便不必直接编辑注入模型的内容。
17. 作为 Fairy，我希望先读取印象再通过有意识的编辑动作修改，以便不会在未看到当前内容时覆盖它，且记忆维护不会顺带重写它。
18. 作为 Fairy，我希望印象直接注入对应用户的上下文，以便每次互动无需先执行检索。
19. 作为用户，我希望印象不因时间流逝自动失效，以便稳定理解不会被周期性重写。
20. 作为 Fairy，我希望每次互动所需的理解、按需回忆的具体记忆和可复用工作流程分别归属印象、长期记忆与 skill，以便同一内容不在三处重复保存。
21. 作为 Fairy，我希望印象编辑有明确长度上限和错误反馈，以便直接注入的内容不会无界增长。

### 记忆工具

22. 作为 Fairy，我希望新增记忆时只需提交内容和可选的 `is_private`，以便接口不暴露无关字段。
23. 作为 Fairy，我希望按关键词检索，并可选择合法闭区间日期，以便缩小查找范围。
24. 作为 Fairy，我希望省略日期时搜索全部日期，以便不因默认时间窗漏掉早期记忆。
25. 作为 Fairy，我希望非法日期边界立即得到错误，以便不会拿到含义不确定的结果。
26. 作为 Fairy，我希望查询结果包含记忆编号、内容、归属用户和内容更新时间，以便后续操作有明确对象。
27. 作为 Fairy，我希望检索日期按最近一次新增或内容编辑计算，以便修改后的记忆按当前内容时间被找到。
28. 作为 Fairy，我希望查询和层级切换不改变内容更新时间，以便查看或隐私调整不会把旧内容伪装成新内容。
29. 作为 Fairy，我希望编辑时提供编号、旧文本和新文本，并要求旧文本恰好命中一次，以便局部修改和整条替换共用一个接口。
30. 作为 Fairy，我希望编辑、删除和层级切换只能作用于当前会话已经查询到的编号，以便不能凭猜测盲改记忆。
31. 作为维护子代理，我希望查询后修改的门禁以本次维护子会话为准，以便源会话中的查询不会替我完成判断。
32. 作为 Fairy，我希望新增、编辑、删除和切换成功时只返回简单确认，以便工具输出不制造额外上下文。
33. 作为 Fairy，我希望检索结果有明确条数和总字符预算并报告截断，以便记忆库扩大不会导致单次注入无界增长。

### 单会话增量维护

34. 作为用户，我希望每个会话独立整理记忆，以便一个会话不会读取或耦合另一个会话的上下文。
35. 作为 Fairy，我希望维护只处理上次完成后的新增闭合用户回合，以便同一区间不会被反复蒸馏。
36. 作为 Fairy，我希望默认累计 15 个闭合用户回合即可形成初始维护门槛，以便按对话进展而非消息条数触发。
37. 作为 Fairy，我希望门槛随区间最新闭合消息的搁置时间下降，以便短小的会话尾部最终也会得到整理。
38. 作为 Fairy，我希望默认每满 6 小时将当前门槛减 1 且最低为 1，以便空区间不会触发维护。
39. 作为 Fairy，我希望只有达到当前门槛且源会话处于静默会话状态时才启动维护，以便不在用户连续对话时插入整理。
40. 作为用户，我希望开始维护时冻结输入区间，以便之后的对话不会被混入本次判断。
41. 作为用户，我希望源会话和维护子会话并行，以便继续聊天不必等待维护结束。
42. 作为维护子代理，我希望只读取用户消息、Fairy 回复、附件名称和记忆变更调用，以便输入保持窄且不重复附件内容。
43. 作为维护子代理，我希望只能使用记忆工具，以便不能读写文件、投递消息或执行其他动作。
44. 作为维护子代理，我希望通过普通与深层检索查找相关旧记忆并自行增删改，以便不依赖另一个裁断 agent。
45. 作为 Fairy，我希望主会话已经发生的记忆新增、编辑、删除和切换出现在维护材料中，以便后续维护不会重复或逆转这些动作。
46. 作为 Fairy，我希望维护完成但零写入也推进水位，以便无意义内容不会被反复检查。
47. 作为用户，我希望维护失败时不推进水位并可从同一子会话恢复，以便重试知道已经执行过哪些记忆操作。
48. 作为用户，我希望重启后按持久水位和当前时间重新计算维护条件，以便进程生命周期不会遗失待整理区间。

### 设置与客户端

49. 作为法厄同，我希望自动压缩触发阈值独立于模型配置，以便切换模型不会改变这项产品策略。
50. 作为法厄同，我希望自动压缩触发阈值默认 500K、可调 100K–900K，以便控制上下文成本与会话寿命。
51. 作为法厄同，我希望压缩保留预算默认 16K token，以便压缩后仍保留近期原文。
52. 作为法厄同，我希望维护触发回合数默认 15、可调 5–50，以便控制维护频率。
53. 作为法厄同，我希望维护门槛衰减间隔默认 6 小时、可调 3–24 小时，以便控制搁置会话的整理速度。
54. 作为法厄同，我希望三个数值项都能通过滑块和直接输入修改，以便兼顾快速调整与精确输入。
55. 作为法厄同，我希望三个控件复用同一套取值、校验和交互组件，以便行为一致且不增加维护成本。
56. 作为法厄同，我希望非法输入在客户端和服务端都被拒绝并说明范围，以便不会静默保存错误配置。
57. 作为法厄同，我希望设置按“上下文／记忆 → 功能 → 参数”的树状归属呈现，以便不与模型或无关配置平铺混杂。
58. 作为法厄同，我希望保存后新的压缩和维护判断采用新值且重启后保留，以便不需要中断正在进行的回复。
59. 作为用户，我希望在普通设置中进入本人印象页，以便无需进入法厄同网关。
60. 作为代理人，我希望不能修改部署级压缩和维护设置，以便共享配置仍由法厄同管理。

### 上下文压缩与恢复

61. 作为用户，我希望原生自动压缩控制单次模型上下文增长，以便长会话不必无限累积历史。
62. 作为 Fairy，我希望绝对阈值与模型自身容量共同限制实际触发点，以便小窗口模型不会等到无法使用才压缩。
63. 作为用户，我希望工具结果裁剪和图片 offload 复用原生能力，以便非文本增长也有处理路径。
64. 作为用户，我希望压缩摘要与长期记忆分开，以便会话延续不会自动生成跨会话事实。
65. 作为用户，我希望原始会话日志继续保存，以便极少数历史追溯可以查看归档会话而不保留失效记忆。

## Implementation Decisions

### 1. 模块与原生接缝

- 新增一个记忆插件，拥有记忆存储、记忆工具、印象、印象用户入口、维护触发和维护子会话。装配只暴露数据库路径、维护模型和 volatile 设置；其他产品模块不直接操作其存储。
- 复用 dsh 的 Agent 创建、Agent setup、工具注册、系统提示、会话日志、SQLite 模式和任务生命周期。维护子会话通过原生 Agent 创建接口运行到完成，不引入完整的通用 subagent 产品面。
- 维护子会话使用独立持久会话、零父上下文和指向源会话的 `parentSession`。子会话不继承用户归属，因此不进入用户的会话列表或会话搜索；源会话归属只由 `parentSession` 解析。其产品预设标识用于只注册记忆工具；其他产品工具在该预设下不注册。
- 原生压缩挂载 token meter、compaction-basic、工具结果裁剪和图片 offload。保留现有 spill，不接入依赖 Typert 的命令压缩面。
- dsh 增加通用的可选绝对 `thresholdTokens` 配置。实际阈值取绝对设置、路由比例阈值和扣除输出预留及余量后的容量三者最小值；未配置时保持原生行为。
- 绝对阈值和维护设置使用 volatile 配置，运行时在下次判断前读取。仅把字段写入配置而仍在构造期缓存，不视为满足热生效。

### 2. 数据结构与权威

- 插件拥有独立的 `memory.sqlite`，使用同步单连接、WAL、版本化迁移和事务。记忆与用户身份库分离，避免扩大身份模块接口。
- `memories` 保存整数编号、正文、数字编码的私密层级、来源会话、创建时间和内容更新时间。编号由 SQLite 的不可复用序列生成。
- 来源会话指向支撑当前内容的会话；新增与内容编辑更新该来源及内容更新时间，层级切换与查询不更新。归属用户由该会话不可变的归属派生，不另建用户关联表。
- `impressions` 每位用户一份当前正文，保存归属用户、创建与更新时间。其他业务表沿用仓库逻辑删除及必要人员、时间字段约定。
- 每个源会话保存维护水位和对应维护子会话身份，用于完成推进、失败恢复和重启重算。
- 查询门禁按实际调用工具的会话记录已返回的记忆编号。主会话与维护子会话的门禁互不借用。
- 失效记忆执行物理 `DELETE`，不保留墓碑行，遵循 ADR-0002；编号不复用。原始会话日志不被删除。
- 记忆检索默认最多返回 20 条、正文总计 8000 个 Unicode 字符；超出预算时截断并在结果元数据中显式报告，调用方不能看到被省略的条目编号后再执行变更。
- 印象默认最大 8000 个 Unicode 字符，写入超限即拒绝，不能静默截断后直接注入。

### 3. 模型工具接口

- `memory_add`：输入 `content` 和可选 `is_private`，默认普通；成功仅返回确认。主 Fairy 的立即新增用于用户明确要求，维护子代理可根据判断新增。
- `memory_search`：输入 `query`、可选的日期边界 `start_at`、`end_at` 和 `is_private`。日期采用毫秒时间戳并组成闭区间；两个边界必须同时提供且开始不晚于结束，缺一个或值非法都报错。两者都省略时搜索全部日期。
- `query` 按字面关键词或短语匹配正文，不做向量、语义扩展或额外重排。查询返回记忆编号、正文、归属用户和内容更新时间，以及条数、字符截断信息；归属用户和日期由后端填充，模型不能选择。
- `memory_edit`：输入 `id`、`old_string`、`new_string` 和可选 `is_private`。目标正文中旧文本必须恰好出现一次；整条替换通过传入完整旧正文表达，不提供 `replace_all`。
- `memory_delete`：输入 `id` 和可选 `is_private`，成功仅返回确认。
- `memory_switch`：只输入全局唯一 `id`，按目标当前层级在普通与私密之间切换，不传 `is_private`，不改变正文、来源或内容更新时间。
- 编辑、删除和切换均要求目标编号已在调用会话的查询结果中出现；新增不受该门禁限制。`is_private` 只选择目标层级，不承担切换语义。
- 印象工具分为读取和整份编辑。Fairy 必须先读取当前印象再编辑；编辑是有意识动作，只在用户明确要求时执行，不随记忆维护自动执行。其中“先读后写”、长度上限与会话归属由运行时强制；“只在用户明确要求时执行”是工具描述对模型的指示，运行时无法证明某次编辑是否来自明确要求。

### 4. 印象与用户入口

- 印象在对应用户的 Agent 系统提示装配时读取并直接注入，不能进入其他用户的上下文；正文描述用户，不承载对 Fairy 自身人格或行为的要求。
- 用户通过独立的印象读取端点查看本人印象；调用者由登录凭据确定，法厄同的管理身份不读取他人印象。用户端不提供编辑入口。
- Fairy 通过工具修改本人会话所属用户的印象，先成功读取才允许编辑；会话归属决定写入对象，不能选择其他用户。
- 印象正文采用纯文本、整份替换，不做段落补丁、版本锁、审批、自动合并或定时重写。
- 印象只保存每次互动都需要的整体理解；具体事实或经历进入长期记忆，可复用工作流程进入 skill，不能双写。

### 5. 维护状态机与材料

- 每个源会话独立维护“上次完成位置、待处理闭合用户回合、最新闭合消息时间”。
- 当前维护门槛等于维护触发回合数减去自最新闭合消息以来经过的完整衰减间隔数，最低为 1。达到门槛且源会话静默时启动。
- 维护触发回合数默认 15、范围 5–50；维护门槛衰减间隔默认 6 小时、范围 3–24 小时。修改设置后按新值重新计算后续触发，不重置既有水位。
- 没有新事件的搁置区间也要按衰减间隔重新评估；重启后依据持久时间和水位重算，不能只依赖进程内定时器。
- 开始维护即冻结本次区间。之后产生的用户消息、Fairy 回复和记忆变更归入下一区间，源会话与维护子会话并行。
- 每个源会话同一时间至多一个维护子会话。完成包括零写入；失败不推进水位，恢复同一子会话以利用已有工具调用记录。
- 材料只包含区间内用户消息、Fairy 回复、附件名称以及记忆新增、编辑、删除和切换调用。附件正文、其他工具输入输出、印象注入、系统提示和压缩摘要不进入材料。
- 维护子代理默认使用部署已有的 MiniMax-M3.1-Flash 轻量模型路由，可配置且不影响主会话模型选择；它只能调用长期记忆的增删查改与层级切换工具，不能编辑印象。它通过普通与深层检索查相关旧记忆并自行决定新增、编辑、删除或全部略过，不增加裁断 agent。
- 维护检索接受常规关键词检索可能漏掉相关旧记忆的已知风险，不增加全库扫描或独立高召回管线。

### 6. 设置树与生效

- 部署级设置分为“上下文 → 自动压缩”和“记忆 → 维护”，不属于模型配置，也不按用户拆分。会话各自计算维护进度，但共用这三项配置值。
- 自动压缩触发阈值默认 500000 token、范围 100000–900000；压缩保留预算默认 16000 token。绝对阈值是产品策略，模型容量仍可把实际触发点压得更低。
- 设置由法厄同网关读取和保存，后端与各自拥有者的 schema 都校验范围；普通代理人的印象读取不经过网关，印象写入只经 Fairy 的工具。
- 保存后，自动压缩在下一次压力判断使用新值，维护在下一次触发评估使用新值；不主动中断正在进行的回复或维护子会话。
- 设置持久化到 dsh profile 用户层，重启后保留。配置读取、校验失败或写入失败必须明确返回，不能把旧值显示成新值已保存。

### 7. Android

- 法厄同网关增加“上下文”和“记忆”分组，分别呈现自动压缩与维护设置；模型配置留在原有独立分组。
- 三个数值项共用一个组合控件：Material 3 滑块、直接数字输入、单位显示、范围校验、忙态和错误反馈。滑块与输入框编辑同一份草稿。
- 自动压缩触发阈值以 K token 显示和输入，持久化仍使用完整 token 整数；另外两项只接受整数。
- 非法直接输入不得保存，也不得被静默改成边界值；服务端拒绝要保留可见错误。
- 普通用户设置增加本人印象入口和独立页面，采用只读的多行纯文本界面；印象的修改通过对话要求 Fairy 完成，页面不提供编辑入口，也不提供长期记忆条目管理页。
- 不新增 UI 依赖；复用现有主题、设置组、导航、网络状态、串行保存和写后重读模式。

### 8. 压缩行为

- 自动压缩触发阈值与模型目录、供应商、端点和模型选择分离，不建立按模型覆盖的产品设置。
- dsh 继续负责 token 计量、保留近期原文、工具配对、压缩事务、溢出恢复和冷恢复。压缩保留预算默认 16000 token。
- 压缩摘要复用原生摘要器和原生模型路由，不新增 Fairy 专用压缩模块，也不把摘要写入长期记忆。
- 原始会话日志与会话摘要具有不同权威；长期记忆失效时物理删除，极少数历史查询通过既有会话检索完成。

## Testing Decisions

### 测试接缝

- 最高层行为测试沿用已经确定的**经过认证的产品会话 Interface**：真实 profile 和 Loader 启动后端，以模型替身驱动真实工具调用、会话日志、SQLite、设置和恢复路径。不能只测内部类或手工拼一个插件就宣称组合可用。
- dsh 的绝对阈值变更在其配置解析和真实 Loader 接缝测试；产品侧通过真实装配证明设置进入原生压缩，而不是复制一套阈值计算供测试使用。
- 维护子会话通过真实源会话和真实子会话验证材料、工具可见性、来源归属和并行行为；轻量模型在确定性行为测试中使用替身。
- Android 通过公共状态、回环 HTTP 和 Compose/Robolectric 页面验证，不让页面各自实现数值或归属规则。

### 必测行为

- 增删查改：默认普通、私密参数、双向切换、唯一匹配编辑、简单成功输出、编号不复用和物理删除。
- 查询：中文关键词、省略日期与合法闭区间、缺单边或非法边界、日期只随新增与内容编辑变化、归属派生、条数与字符截断。
- 门禁：未查询不能编辑、删除或切换；其他会话的查询不能授权；维护子代理必须自己查询；新增后必须查询才能变更。
- 印象：本人只读、管理身份也不能读他人、写入只经 Fairy 工具且先读后写、直接注入只进入对应用户、超长拒绝、非定时失效。
- 维护：15 回合默认值、5–50 配置、3–24 小时间隔、每完整间隔减 1、最低 1、静默准入、搁置后重评、零写入推进、失败恢复和重启重算。
- 并行与材料：开始维护后的消息进入下一区间；附件只传名称；只传记忆变更调用；子会话没有其他工具、没有其他主会话上下文；来源归属正确。
- 设置：三个范围的客户端与服务端校验、滑块与直接输入同步、保存后热生效、重启保留、普通代理人拒绝修改、绝对阈值不随模型选择改变。
- 原生压缩：较小模型窗口会压低实际触发点、16K 保留、工具结果裁剪、图片 offload、压缩后会话继续及冷恢复。
- 迁移与故障：旧 schema 升级、非法配置响亮失败、写入失败不推进维护水位、恢复同一维护子会话。

### 质量验证

- 另设不进入 CI 的真实轻量模型验收样本，覆盖明确偏好、用户明确要求记住、无意义寒暄、易变且不确定的观察、当前事实更新、失效删除、私密切换和跨用户分寸。模型替身测试通过不能代替这批语义质量验收。
- 验收记录实际写入、略过、修改和删除结果，特别检查“没有值得处理的内容就直接结束”与“失效内容不继续检索”。

### 既有先例与最终门禁

- 复用会话搜索、身份归属、网关保存与重启、真实 Loader、配置错误、Android 网关线协议、状态串行保存和设置页测试的既有模式。
- 相关改动先跑对应后端、dsh 和 Android 测试；最终集成状态执行 `npm test`、`npm run combo:verify` 和 Android 的 `test`、`lintDebug`。dsh 变更同时满足其类型、文档生成和覆盖门禁。
- 真实模型质量验收单独记录，不与模型替身、构建成功或静态源码检查混为一谈。

## Out of Scope

- DREAMING、日记、外部感官和通用主动任务策略。
- skill 系统的实现，以及工作流经验的自动学习。
- 向量检索、embedding、RAG、知识图谱、外部记忆服务和图数据库。
- 长期记忆全库的客户端直接查看或编辑器。
- 自定义会话压缩算法、通用 subagent 产品面、跨会话统一维护调度器。
- 旧 Fairybot 数据自动迁移、记忆回收站、失效记忆审计和版本回滚。
- 按模型设置自动压缩触发阈值，或由普通用户修改部署级配置。

## Further Notes

- 外部项目的一手调研见 `docs/research/2026-10-26-context-memory-dreaming.md`。旧 Fairybot 的可取部分主要是证据锚点、幂等水位、材料筛选和失败恢复纪律，不是直接迁移其 vendored 内核。
- dsh 官方当前没有长期记忆插件；社区实现只作为机制参考。本规格不引入 Mem0、Letta、Graphiti 或 LangMem 依赖。
- 失效物理删除及其与通用业务表逻辑删除规则的关系由 ADR-0002 记录。
- 本规格可作为 #112 所设想的记忆插件依赖，但不完成该票的日记、节律、关系或外部感官决策；外部感官不得另建平行记忆权威。
- #118 关注的 30 天／1 年成本与失效曲线仍需真实运行数据。本规格给出实现与验收入口，不预先宣称长期质量结论。
- 首版总规格中记忆、印象蒸馏和子代理的排除只适用于首版范围；本规格是后续独立增量，不改变既有首版验收承诺。
