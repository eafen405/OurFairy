# 优先跟进官方上游，按维护成本选择扩展接缝

OurFairy 优先保持跟进 dsh 官方更新的能力；社区插件和工具以低集成成本接入，两者冲突时官方更新优先。原因是官方模块演进需要持续跟进，而用户愿意为合适的社区插件承担局部二次开发成本。

产品规则优先通过原生接口在 OurFairy 中实现。原生接口确实缺少必要能力时，允许维护少量职责明确的通用补丁；评估须同时计入外置替换所需复制或持续追随的上游行为。

接缝应集中复杂性。判断成本时检查调用方需要了解的内部细节、受变化影响的消费者，以及协调工作的生命周期和顺序要求。引入浅模块需要说明具体收益与代价；无关职责不因共用一个调度器而集中到一起。

这项选择接受必要补丁的持续验证成本。若一个扩展持续牵动更多无关模块，应重新评估接缝及对应产品行为；权限隔离、数据可靠性等必要保障仍需保留。

确认过程与固定源码依据见[设计校准记录](../decisions/upstream-compatibility-calibration.md)。具体补丁的保留、收缩或替代方案在该记录中继续讨论。
